# 構造 —— 既存概念と作者の提唱

530 の Gist から働き方の記述を集めて分けると、はっきりした構造が出てくる。ここではそれを論じる。

## 1. 二系統に分かれる、が分かれ方が特殊である

素朴に分ければ「既存概念」と「作者の提唱」になる。実際 [既存概念カタログ](existing_concepts.md) には 100 以上の既製品が並び、[コラボレーションモジュール](collaboration_modules.md) には 80 以上の造語が並ぶ。

だが分かれ方が独特である。作者は既存概念を **紹介しない**。必ず **不足を特定して、その穴に自分の語を置く**。

| 既存概念 | 作者が見つけた不足 | 作者の語 |
|---|---|---|
| 心理的安全性 | 同期・対面の場を暗黙の前提にしている | [非同期心理的安全性 (APS)](aps.md) |
| 合理的配慮 | 既存規範が先にあり、譲る側が譲る量を決める | [個別的配慮](diversity_implementation.md) |
| Collaboration Engineering | 再現性と引き換えに判断を奪う | [scripty / 判断尊厳](scripty_and_dignity.md) |
| ABW / フリーアドレス | 「器用な者」にしか合わない | [ホフィス](hoffice.md) |
| チームワーク | 合意形成コストに思考を食われる | [ソロワーク](solowork.md) |
| マイクロマネジメント | その一段手前の高頻度介入に名前がない | [ミリマネジメント](millimanagement.md) |
| 成果主義 (ROWE 等) | 成果が測れない仕事では代理変数に戻る | [管理3.0](management3.md) |
| VUCA | リモートと多様性が抜けている | VUCARD |
| ウォーターフォール／アジャイル | 探索を扱う枠がない | [エクスプロラトリ](exploratory.md) |
| ハラスメント概念 | 善意の同期共有が抜けている | [FYIハラスメント](fyi_harassment.md) |

**既存概念の不足点が、そのまま造語の設計図になっている。** だから二系統は対立していない。**接続している。** 作者自身の表現を借りれば「既存の宇宙に新しい星を足す」型である。

## 2. すべての造語が、一つの軸を測っている

80 個以上の造語を並べても散らかって見えないのは、全部が同じものを測っているからだ。その軸に作者は名前を与えている——**拘束** である。

[コミュニケーション拘束パラダイム](full_four.md) は、拘束を四つに分けた。

- **場所の拘束** → フルリモート
- **時間の拘束** → フルフレックス、[クロノ・ダイバーシティ](diversity_implementation.md)、[シームレスなコアタイム](collaboration_modules.md)
- **話題の拘束** → フルアシンク、[NXD](nxd.md)、[時限切断](nxd.md)
- **身元の拘束** → フルマスク、[マスクド・アイデンティティ](full_four.md)、クローズドな匿名

そして突破レベル Lv0〜Lv5 という物差しがつく。**ハイブリッドワークは Lv3 にすぎない。**

この一本の軸に、残りのほぼ全部が並ぶ。[働き方の8軸診断](collaboration_model_dimensions.md) の 8 軸は拘束の測定項目である。[管理3.0](management3.md) は拘束の少ない管理形態である。[ソロワーク](solowork.md) は同期密度という拘束の引き下げである。[Human as Agent](human_as_agent.md) は関係性という拘束の引き下げである。

**作者は多様な道具を作っているのではなく、一つの思想を 80 の接点で実装している。**

## 3. 三層構造 —— 診断・命名・設計

Gist を時系列と密度で見ると、作者の思考は必ず三段階を通る。

**第一層: 診断（何が起きているか）**

[原始的な働き方](primitive_workstyle.md) の「意思決定層の認知的同質性」。[出社回帰の本当の理由](rto_incentives.md) の四つのインセンティブ。[会社という名の村](japan_village.md) の「契約も責任も曖昧だから村化する」。[孤独と禁欲の組織論](solitude_and_abstinence.md) の「バグではなく仕様」。

診断の特徴は、**原因を人格ではなく構造に置く** ことである。上司が悪いのではなく、対面重視の人が出世する構造がある。経営者が愚かなのではなく、非同期化で最も失う層が決定権を持っている。

**第二層: 命名（何と呼ぶか）**

[名前をつけるという仕事](naming_as_work.md) で見たとおり、命名は診断を **選択肢に降格させる** 操作である。無名のものはデフォルトに見えるが、名前がつけば「選ばれたもの」になり、選ばなかった理由を問える。

だからレトロニムが多用される。チームワーク、Fixed Role Paradigm、同期版の心理的安全性——**すでにあったものに、後から名前をつける**。

**第三層: 設計（どう置き換えるか）**

[出社ポイント制度](office_point_system.md)、[ホフィス](hoffice.md)、[NXD](nxd.md)、[MAMA](management3.md)、[社内仕事マーケットプレイス](internal_job_marketplace.md)。

設計の特徴は、**意識ではなく仕組みを変えること** である。作者は一度も「マインドセットを変えよう」と言わない。出社を我慢するのではなく、出社にポイントという価格をつける。長文を歓迎する空気を醸成するのではなく、[「長文歓迎、既読プレッシャーなし」を規約として制定する](aps.md)。

> 心理的安全性が空気として醸成されるものなら、こちらは**規約として制定できる**。

## 4. 違和感の出どころ —— 四つの水源

作者の一次的な違和感を辿ると、水源が四つに絞れる。

**(a) 同期への怒り**。会議、出社、割り込み、即レス。[FYIハラスメント](fyi_harassment.md)、[ミリマネジメント](millimanagement.md)、[NXD](nxd.md)、[ソロワーク](solowork.md) がここから出る。核心は時間の消費ではなく **思考の配分先** への怒りである——「コミュニケーションと合意形成以外で頭を使えていない」。

**(b) 暗黙への怒り**。空気、根回し、慣行、口頭主義。[透明主義](collaboration_modules.md)、[RAIS](collaboration_modules.md)、[APS](aps.md)、[会社という名の村](japan_village.md) がここから出る。暗黙のルールは、それを自然に読める人だけを通すからだ。

**(c) 単一標準への怒り**。「ふつう」を一つ決めて、外れた人に例外措置を与える構造。[個別的配慮](diversity_implementation.md)、[クロノ・ダイバーシティ](diversity_implementation.md)、[Full Four](full_four.md)、[「条件を持たない個人」](conditionless_individual.md) がここから出る。

**(d) 判断の剥奪への怒り**。[scripty と判断尊厳](scripty_and_dignity.md)、[エクスプロラトリ](exploratory.md)、[AI時代の認知的降伏](ai_era_work.md)。これだけが効率の話ではなく **尊厳** の話である。そして最も射程が広い。

四つは独立ではない。(a) 同期は (b) 暗黙を運び、(b) 暗黙は (c) 単一標準を強制し、(c) 単一標準は (d) 判断を不要にする。**一本の因果の鎖である。**

## 5. 対立ではなく「順序」の主張である

作者の提言を「リモート vs 出社」「非同期 vs 同期」の対立と読むと、外す。作者は繰り返し **順序** を主張している。

- 非同期を **デフォルト** に、同期を **オンデマンド** に（[デフォルト・フレキシブル](full_four.md)）
- 「新人とキックオフだけ対面」は合理の範囲内（[出社回帰](rto_incentives.md)）
- script 的な設計は安全性・監査性の場面では有効。問題は過剰な正当化（[scripty](scripty_and_dignity.md)）
- 砕けない仕事は砕かない（[社内仕事マーケットプレイス](internal_job_marketplace.md)）
- 組織は乾いていていい。ただし **可処分時間を返すこと** が前提（[孤独と禁欲](solitude_and_abstinence.md)）

敵は同期でも出社でもない。**粒度の粗さ** である。[第三の切り口](third_lens.md) の「出社かリモートかの二択にしてしまう時点で設計能力が足りていない」が、この Wiki の一貫した立場である。

## 6. 空白 —— 論じられていないこと

正直に言えば、この体系には穴がある。

**統合の設計がない**。[Independent Parallel](solowork.md) は「どのアウトプットを選ぶか、どのように統合するか」を明示的に射程外にしている。[エクスプロラトリ](exploratory.md) も同じ。**バラして並べる設計は充実しているが、集めて決める設計が薄い。**

**説得の設計がない**。collaboration-modules は「説得はこのリポジトリの責務ではない」と明言する。だが [出社回帰の本当の理由](rto_incentives.md) で作者自身が書いたとおり、非同期化で最も失う層が決定権を持っている。**説得を放棄すると、決定権のある層には届かない。** 唯一の攻め筋として提示されているのが、[原始的な働き方](primitive_workstyle.md) の「会議と並走させて既成事実を積む」という戦術である。

**サイトバウンド職が射程外**。[フルリモートを支える側](remote_support_side.md) で作者自身が認めている。24 時間 365 日のシフトで回る現場職は、ナレッジワーカー向けの理論の外にある。

**金銭の設計が薄い**。出社手当、シフト差額、住宅補助。同じ回で作者が自著の弱点として挙げている。

## 7. 全体を一行で

作者がやっているのは、**働き方を「文化」から「設計対象」へ移す作業** である。

文化は変えられない。だから普通は諦めるか、意識改革に走る。作者は第三の道を選ぶ——**文化を変えずに、文化が悪さをしにくい仕組みを作る。**

そのために必要なのが、制度より細かい粒度の道具である。それが 80 個の [コラボレーションモジュール](collaboration_modules.md) であり、それを作れるのはエンジニアだ、というのが [第三の切り口](third_lens.md) の主張である。
