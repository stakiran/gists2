vltについて最新情報を検索しますね。vlt(発音は "volt")は、npmの創設者Isaac Schlueterや元npmコアメンテナーたちが立ち上げた新しいJavaScriptパッケージマネージャーです。2024年11月のNodeConf EUでパッケージマネージャー本体と、サーバーレスレジストリ「vsr」が公開されました。ちょうどタイムリーなことに、2026年8月4日にvlt 1.0が正式リリースされ、ホスト型パッケージレジストリとエコシステムミラーの一般提供も開始されたばかりです。

## npmとの主な違い

**1. インストールとビルドの分離(最大の特徴)**

従来のパッケージマネージャーはインストール時にライフサイクルスクリプトを自動実行しますが、これは悪意あるパッケージが任意コードを実行できるセキュリティリスクです。vltはこれを2つのフェーズに分離しました:installフェーズ(ダウンロードと展開のみ、スクリプト実行なし)とbuildフェーズ(選択したパッケージのライフサイクルスクリプトを実行)。vlt buildはデフォルトで既知のマルウェアを持つ依存関係のスクリプト実行から保護してくれます。

**2. セキュリティファーストな設計**

パブリックパッケージへのすべてのリクエストがセキュリティレイヤーを通過し、既知のマルウェアや高リスクなソフトウェアを自動ブロックします。ライフサイクルスクリプトはデフォルトで制限・無効化され、危険な動作には明示的な承認が必要です。

**3. DSS(Dependency Selector Syntax)クエリ言語**

CSSセレクタ風の構文で依存関係グラフを調べられます。1.0時点で60以上のセレクタがあり、うち約30がセキュリティ関連(:malware、:cve、:unmaintained、:outdated、:vuln など)。:host(local)を使えばマシン上の全プロジェクトを横断してクエリでき、例えば `vlt query ':host(local) #react:v(<19)'` で古いReactを使っているプロジェクトを検索できます。Mermaid形式などへのエクスポートやGUIで、依存グラフの理解を容易にするのも特徴です。

## 使い方

インストールはnpm経由で `npm install -g vlt` が一般的です(Node.js v20とv22でサポート、情報が古い可能性があるので最新要件は公式ドキュメント参照)。

基本コマンドはnpmとほぼ同じ感覚で使えます:

```bash
vlt install react        # パッケージのインストール(スクリプトは実行されない)
vlt build                # ライフサイクルスクリプトの実行
vlt run dev              # scriptsの実行
vlt query "..."          # 依存グラフのクエリ
```

npmから移行してきた場合、installに続けてbuildを実行するのが従来のパッケージマネージャーの動作と機能的に等価です。どうしても従来のnpmのように全ライフサイクルスクリプトを実行したい場合は `--allow-scripts="*"` オプションでオプトインできます。設定はvlt.jsonファイルに書き込むことで、コマンド実行時に毎回指定する必要がなくなります。

## 互換性

かなり高いです。ほとんどの場合、既存のパッケージマネージャーのドロップイン代替として機能します。デフォルトではpublic npm registryからパッケージをインストールするため、npmで公開されているパッケージをそのまま利用できます。package.jsonもそのまま使えます。

ロックファイルは独自の `vlt-lock.json` を使います(package-lock.jsonとは別物)。エコシステム側の対応も進んでいて、Vercelではvlt-lock.jsonがあるプロジェクトは自動的にvlt installがデフォルトのインストールコマンドになります。レジストリ側のvsrもnpm、yarn、pnpm、deno、bunとの互換性を持って提供されています。

注意点としては、比較的新しいツールなのでコミュニティやエコシステムの規模はnpm/pnpm/yarnにはまだ及ばないこと、そして「スクリプトを実行しないinstall」という思想の違いにより、ネイティブモジュール(node-gypでビルドするもの等)を含むプロジェクトでは `vlt build` を忘れると動かない、という点に慣れが必要です。試すなら、既存プロジェクトでnode_modulesを消して `vlt install && vlt build` してみるのが手っ取り早いです。
