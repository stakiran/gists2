# Claude Code の mod まとめ

> 調査時点: 2026-10 / Claude Code v2.1.287 時点の公式ドキュメントに基づく。
> イベントや API はリリースごとに変わりうるので、最終的には手元のバージョンが生成する型定義（`.claude-plugin/types/claude-code/index.d.ts`）を正とする。

## TL;DR

- **mod = Claude Code の内部イベントに割り込む TypeScript / JavaScript の関数を持ったプラグイン**
- 「Claude Code のミドルウェア」。ツール呼び出し・プロンプト・モデルへのリクエスト・画面描画などに、前・後・代わりに処理を挟める
- 従来の Hooks と違い **Claude Code のプロセス内で動く** ので、UI の描き換えやシステムプロンプトの改変までできる
- 自分で書いても、Claude Code に「〜する mod 作って」と頼んで書かせてもよい
- できることは **公開されているイベント × mods API (`$`) × 描画先** で決まる
- 要件: Claude Code **v2.1.287 以降**（デフォルトで有効）。CLI とデスクトップアプリの Code タブで動作

---

## 1. 従来の拡張との違い

| | mod | Hooks（settings） | Skills | MCP サーバー |
|---|---|---|---|---|
| 正体 | Claude Code が自プロセス内で呼ぶ関数 | イベント時に実行されるシェルコマンド / HTTP / プロンプト | Claude が読む SKILL.md | ツールを提供する外部プロセス |
| 変えられるもの | ツール呼び出し、プロンプト、コマンド、ターン、UI 描画 | ツール呼び出しの可否・引数・結果、Claude への追加文脈 | Claude の知識・振る舞い | Claude が使えるツール |
| UI を描けるか | ✅ | ❌ | ❌ | ❌ |

「Hooks の一種か？」→ **半分 Yes**。mod の中身は「フック」と呼ばれるイベントハンドラの集まりだが、settings.json に書く従来の Hooks 機能とは別物。
従来の Hooks は外部でコマンドを走らせるだけ、mod は内部でイベントの中身を書き換えたり乗っ取ったりできる。

## 2. ファイル構成と書き方

JSON は設定だけ。本体は JS / TS。Node.js・バンドラー・ビルド不要（`.js` / `.ts` を直接ロード）。

```text
my-mod/                       ← mod のルート（置き場所は自由）
├── .claude-plugin/
│   └── plugin.json           ← マニフェスト（通常のプラグインと同じ）
└── hooks/
    ├── hooks.json            ← modules でコードの場所を指す（これがあると mod になる）
    └── register.js           ← 本体（hooks module）
```

**plugin.json**

```json
{
  "name": "my-mod",
  "version": "0.1.0",
  "description": "ツール呼び出しを数える mod"
}
```

**hooks/hooks.json**

```json
{
  "modules": ["./register.js"]
}
```

**hooks/register.js**

```js
let count = 0

// ロード時に一度呼ばれる。on でフックを登録する
export function register(on) {
  // ツール実行の直前
  on('tool.call', async ($, e, next) => {
    count++
    $.ui.invalidate('ui.render') // 再描画を依頼
    return next(e)               // ツールは通常どおり実行
  })

  // スピナー描画時だけ（第2引数はマッチャー）
  on('ui.render', { component: 'Spinner' }, async ($, e, next) => {
    return next({ ...e, props: { ...e.props, suffix: ` · ${count} tools` } })
  })
}
```

### フックの3引数

| 引数 | 中身 |
|---|---|
| `$` | mods API。ファイル・プロセス・ネットワーク・UI などに触る窓口 |
| `e` | イベントの入力（凍結されたプレーンデータ）。変えたいときはコピーを `next` に渡す |
| `next` | 次の mod → Claude Code 本来の処理へ渡す関数 |

### フックの3つの振る舞い

- **観察**: `return next(e)` — 素通し
- **改変**: `return next({ ...e, 変更 })` — 中身を書き換えて流す
- **乗っ取り**: `next` を呼ばずに自分で結果を返す

### 開発サイクル

```bash
claude --plugin-dir ./my-mod          # インストールせず1セッションだけ読み込む（保存でホットリロード）
claude plugin validate ./my-mod       # フックしているイベントと呼んでいる API を静的解析で表示
claude plugin test                    # *.test.ts を実行
```

### 静的解析を通すための注意

- イベント名は文字列リテラルで書く（変数やループは NG）
- `$` を変数に代入・分割代入しない（`const ui = $.ui` は NG）。`$.ui.open(...)` のようにフルで書く
- `require` ではなく `import`、動的 `import()` も NG
- プラグインディレクトリ外からは import しない（例外は型用の `claude-code`）

### いちばん楽な方法

Claude Code のセッションで「現在の git ブランチをプロンプトの上に出す mod を作って」のように頼む。組み込みスキル `/plugin-authoring` を使って Claude が書き、ホットリロードまでしてくれる。

## 3. どこに置かれるか

`.claude/skills/` のような決まった「mods フォルダ」はない。**mod のディレクトリ自体がルート**。

| 読み込み方 | 場所 |
|---|---|
| Claude に書かせた | `~/.claude/dev-mods/<セッションID>/<mod名>/`（一時的。そのセッション専用で、`cleanupPeriodDays` 経過後に削除。残すなら自分の場所へコピー） |
| 自分で開発 | どこでも可。`--plugin-dir` か環境変数 `CLAUDE_CODE_PLUGIN_DIRS` で指定 |
| マーケットプレイスからインストール | 実体は `~/.claude/plugins/cache`、有効化情報は settings.json の `enabledPlugins` |

### チームで共有する場合

- マーケットプレイスに載せ、リポジトリの `.claude/settings.json` に `extraKnownMarketplaces` と `enabledPlugins` を書いてコミット
- ただし **コミットしても有効化の宣言になるだけで、ダウンロードはされない**。各メンバーが一度 `claude plugin install <name>@<marketplace> --scope project` を実行する必要がある
- スコープ: user = `~/.claude/settings.json` / project = `.claude/settings.json` / local = `.claude/settings.local.json`

## 4. できること網羅

### 4-1. 割り込めるイベント

| 分類 | 主なイベント | できること |
|---|---|---|
| ツール | `tool.call` `tool.check` `tool.describe` | 実行拒否・引数改変・結果を自前で返す、許可判定（allow / ask / deny）の上書き、ツール説明の書き換え |
| プロンプト | `prompt.submit` `prompt.compose` `prompt.section` `prompt.context` `prompt.attachment` `skill.prompt` | 入力の書き換え・破棄・文脈追加、**システムプロンプトをセクション単位で改変・削除**、リマインダーの差し替え、スキル本文の改変 |
| 入力欄 | `prompt.fill` `prompt.suggest` `prompt.edit` | 下書き・サジェストの変更 |
| コミット | `attribution.text` | コミット / PR の署名テキスト変更 |
| コマンド・設定 | `command.run` `command.describe` `config.set` `config.describe` | スラッシュコマンドの乗っ取り・非表示、`/config` 変更の拒否 |
| ターン | `turn.start` `turn.step` `turn.complete` | **リクエストごとにモデルや effort を切り替え**、回答の下に1行表示 |
| セッション | `session.start` `session.end` `session.compact` `session.append` `session.send` `session.receive` | 圧縮のスキップ、保存される会話ログの書き換え、セッション間メッセージ制御 |
| サブエージェント | `agent.offer` `agent.spawn` | サブエージェントを Claude に見せない、起動拒否・モデル変更 |
| UI | `ui.render` `ui.press` `ui.input` `ui.select` `ui.focus` `ui.scroll` `ui.close` `ui.message` | 描画の差し替え、自作コントロールへの反応 |
| 他の mod | `plugin.register` `engine.create` | 他の mod のロード拒否、他の mod に渡す API の追加・剥奪 |
| テレメトリ | `telemetry.log` `telemetry.mark` | ログ記録の拒否 |

補足:

- 従来の settings hooks も `classic.<イベント名>`（例: `classic.Stop`）として拾える
- **mods API の呼び出し自体もイベント**（`fs.read` `model.complete` など）。後続 mod の呼び出しを横取りできる

### 4-2. mods API (`$`)

| 名前空間 | 内容 |
|---|---|
| `$.ui` | ペイン開閉、トースト、ステータス、ログ、確認ダイアログ（`ask`）、コピーなど |
| `$.command` `$.tool` `$.agent` | **独自コマンド・Claude 用ツール・サブエージェントの登録**、既存の呼び出し |
| `$.model` | `complete` `fork` `classify` — mod から直接モデルを呼べる |
| `$.prompt` | プロンプト送信でターン開始（ユーザー発言として送ることも可） |
| `$.turn` | 実行中ターンの中断 |
| `$.session` | 履歴、cwd、リポジトリ、モデル、コンテキスト使用率・レート制限・コスト、圧縮、他セッションへの送信 |
| `$.fs` `$.process` `$.http` `$.mcp` | ファイル読み書き、**コマンド実行**、HTTP、MCP 呼び出し |
| `$.store` `$.state` | マシン内全セッション共有の KV ストア、リアクティブ状態 |
| `$.clock` | タイマー・定期実行 |
| `$.env` `$.settings` `$.config` | 環境変数、設定の読み取り・変更 |
| `$.audio` | 再生、読み上げ |

### 4-3. 描画

**描画先（render site）**: 自作ペイン（`Pane`）、プロンプト上の帯（`AbovePrompt`）、ユーザー / アシスタントのメッセージ、ツール呼び出しと結果、コマンド出力、質問ダイアログ（`AskUserQuestion`）、スピナー、所要時間、通知、モード表示、入力ヒントなど

**既存の描画への3択**: 細部だけ変える / 丸ごと置き換える / そのまま（`next(e)`）

**部品（element）**: `Box` `Text` `Markdown` `Link` `Code` `Button` `Input` `Select` `Client`、ターミナルのみ `Raster` `Image`、デスクトップのみ `Svg`

不正な要素や props を含むツリーを返すと、Claude Code は自前の描画にフォールバックする（壊れても画面は崩れない）。

## 5. 制約・セキュリティ

- **許可確認プロンプトはレンダーサイトではないので変更不可**
- ユーザーが入れた mod が `deny` ルールを覆すには、管理者側で `allowModsToOverrideDenyRules` の有効化が必要
- 主な上限: フック1回 10 秒 / ファイル読み書き 1 ファイル 4 MiB / `$.store` 合計 4 MiB / 再描画は秒間 10 回（表示中ペインと帯は 30 回）
- フックが失敗・タイムアウトすると Claude Code はそれをスキップしてセッションを続行する（壊れた mod は「何もしない mod」に見える）
- mod は **インストールしたユーザーの権限で動くコード**。信頼できる提供元のものだけ入れる
- 組織向け: `allowManagedModsOnly`（組織の mod だけ許可）、`disableSideloadFlags`（`--plugin-dir` 禁止）、`prependPlugins` / `appendPlugins`（実行順の固定）など
- `--safe-mode` で起動すると mod は読み込まれない

---

## 6. 結論

できることは「公開されたイベント × mods API × 描画先」次第。ただし `$.process` `$.http` `$.fs` `$.model` まで揃っているので外の世界にはほぼ手が届く。
mod の本領は、**システムプロンプト・ツール説明・モデル選択・会話ログ・UI といった、これまで外から触れなかった Claude Code の内側に割り込めること**。逆にイベントとして公開されていない部分（許可プロンプトなど）には触れない。

Anthropic は今後、組み込み機能をさらに mod に移し、小さなコアに必要な機能だけ足せる形にしていく方針。
