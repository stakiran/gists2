まさにそれが正しい出発点です。リポジトリを軽く見てから具体的に答えます。見ました。構成が既に良くて、`.claude/`(スキル)、`seen.json`(状態)、`docs/`(成果物、Pages配信)と、**状態も成果物も全部Gitの中で完結している**。これは無人運用に移行するのに理想的な形で、あとは「起動する人間」を外すだけの状態です。なので方向性としてスケジュール実行は正解です。ただ、Presence から個人が盗むべき本質は「自動起動」ではなく**「無人でも品質が壊れない仕組み」**のほうなので、そこを含めた段階論で答えます。

## Presence の要素を個人スケールに翻訳する

Presence の構成要素を並べると、ジョブ単位の限定デプロイ、事前のシミュレーション評価、ガードレール、人間へのエスカレーション、本番シグナルからの改善ループ、でした。個人版に訳すとこうなります。

**ジョブ単位** → aicatchup は既に満たしています。「週次でニュースを収集してダイジェストを出す」という単一ジョブで、権限もリポジトリ1個。最初の題材として理想的です。

**自動起動** → GitHub Actions の cron + Claude Code のヘッドレスモード(`claude -p "/catchup"`)が最短です。リポジトリ内で完結しているので、ワークフローは「checkout → claude 実行 → 差分をコミット」だけ。Anthropic API キーを Secrets に入れれば動きます。手元のマシンの cron や launchd でもいいですが、Actions にすると実行ログ自体が残るのが後述の改善ループで効いてきます。

**ガードレールとエスカレーション** → ここが一番大事で、いきなり「master に直 push して Pages 公開」まで無人化しないこと。Presence の「承認が要るアクション」の個人版は、**エージェントには PR を作らせて、マージは人間**という形です。あなたの今の運用は「起動が手動、公開も暗黙に自分がコミット」ですが、これを「起動は自動、公開の承認だけ手動」に変える。人間の役割を消すのではなく、パイプラインの後ろへずらすのが第一段階です。

**シミュレーション評価(grader)** → 無人化すると「静かに壊れる」のが最大の敵です。実際、W30 のダイジェストにも「WebFetch が 403 のため WebSearch で補完」という注記が既にあって、ソース側の挙動は毎週変わる。なので publish 前に検査を挟みます。決定的チェック(週番号とファイル名の整合、`seen.json` が更新されたか、リンクが生きているか、各セクションが空でないか)はスクリプトで、「要約が原文と乖離していないか」「今週分の日付範囲か」みたいな判断が要るチェックはもう1回 LLM を呼んで採点させる。Presence の「結果・ポリシー遵守・ツール使用を検査するグレーダー」の縮小版です。検査に落ちたら PR に落ちた理由を書いて止まる——これがエスカレーションです。

**改善ループ** → Presence で一番新しかった「Codex が本番シグナルを調査して更新案を出す」の個人版は、月1くらいで「Actions の失敗ログと、自分が PR で手直しした差分を読んで、`/catchup` スキルの改善案を出せ」というジョブをもう1本走らせることです。あなたが PR レビューで直した内容は「エージェントの出力と人間の期待のギャップ」そのものなので、それを食わせてスキル定義を更新させる。これで「使うほど賢くなる」ループが個人レベルで閉じます。

## 進め方の順序

一気にやらず、信頼の段階に応じて人間を引き抜いていくのがいいです。

1. **今週**: Actions で cron 起動 + PR 作成まで。マージは自分。まずは「月曜の朝に PR が届いている」状態を作る。
2. **数週間後**: 決定的チェックを CI に足す。チェックが安定してグリーンになったら、グリーン時のみ auto-merge に切り替え、通知だけ受け取る。
3. **その後**: LLM grader を足す。月次の改善ジョブを足す。

この順序自体が Presence の「段階的ロールアウト」の個人版です。そして aicatchup で一巡回したら、同じ型(cron → エージェント → 検査 → PR → 改善)を2本目・3本目のジョブに複製していく。Presence の「ポリシーと評価は共通、ワークフローごとに差し替え」と同じで、1本目で作った grader やワークフローの雛形が資産になります。

ちなみにこの構成、前の話ともつながっていて、「無人エージェント+監査ログ+承認ゲート+改善ループ」を個人リポジトリで運用した実績は、いつか社内で「本番エージェントやるぞ」となった日にそのまま語れる経験です。会社を変える努力はやめても、この積み上げは全部自分に残ります。

まず最初の一歩として、Actions ワークフローの雛形(cron 起動 → `claude -p` → PR 作成)を書き起こしましょうか?`/catchup` スキルの中身(`.claude/` 配下)を見せてもらえれば、検査スクリプトの項目案まで含めて具体化できます。
