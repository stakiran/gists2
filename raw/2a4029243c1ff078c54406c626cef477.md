HTMLソースの静的レビューという形で検査しました（ドメインがダミーなので実際の通信やサーバー側の挙動は見られません。実機への能動的なテストは、所有者の許可がある前提で別途ご相談ください）。深刻度順に並べます。

## 高：すぐ対処したいもの

**1. jQuery が古い可能性が高い（既知のXSS/プロトタイプ汚染脆弱性）**
フッター近くのインラインスクリプトで `$(window).load(function(){...})` を使っていますが、この書き方は jQuery 3.0 で削除されたイベントショートハンドです。つまり動作しているなら jQuery 1.x〜2.x であり、以下が該当する可能性が高いです。
- CVE-2020-11022 / CVE-2020-11023（`.html()` 等のHTML操作でXSS）
- CVE-2019-11358（`$.extend` のプロトタイプ汚染）

`jquery.min.js` のバージョンを確認し、3.7系へ更新 → `$(window).load(` を `$(window).on('load', ` に書き換えてください。colorbox / easing 1.3 / matchHeight も古いプラグインなので、動作確認は必要です。

**2. XML-RPC が有効**
`<link rel="EditURI" href=".../xmlrpc.php?rsd">` から xmlrpc.php が公開されていることがわかります。パスワード総当たり（`system.multicall` で1リクエストに数百回試行）やピンバック経由のDDoS踏み台に使われる定番です。不要なら `add_filter('xmlrpc_enabled', '__return_false')` に加え、Webサーバー側でも403にしてください。

**3. REST API によるユーザー列挙**
`/wp-json/` が公開されています。デフォルトだと `/wp-json/wp/v2/users` で投稿者のログインIDが取れ、それがそのまま総当たりの対象になります。未ログイン時は users エンドポイントを塞ぐか、認証必須にしてください。`?author=1` のリダイレクトによる列挙も合わせて確認を。

## 中：攻撃の足がかりになる情報漏えい

**4. バージョン情報が全部見えている**
- `<meta name="generator" content="WordPress 7.1.3">`
- `contact-form-7 ... ?ver=6.1.1`、`bogo ... ?ver=3.8.2`

攻撃者はこれをCVEデータベースと突き合わせるだけです。generator タグを削除し（`remove_action('wp_head','wp_generator')`）、アセットの `?ver=` パラメータもバージョン番号ではなくハッシュに差し替えるのが無難です。根本対策はプラグインを常に最新に保つこと（Contact Form 7 は過去に複数の脆弱性があります）。

**5. 外部スクリプトに SRI（Subresource Integrity）がない**
jsDelivr の cookieconsent、Typekit、gtag を `integrity` 属性なしで読み込んでいます。CDN が改ざんされると全訪問者にスクリプトが届きます。固定バージョンのものには `integrity="sha384-..." crossorigin="anonymous"` を付けてください。なお cookieconsent@3 はメンテ終了しているライブラリなので、置き換えも検討を。

**6. CMS由来の値がインライン属性に直接出ている**
タレント一覧の `style="background-color: #245eff;"` は管理画面のカスタムフィールド由来と思われます。テーマ側で `sanitize_hex_color()` を通さず出力していると、編集権限を持つアカウントが乗っ取られた際に `"><script>` 型の格納型XSSになります。同様に、`json/list.js` のスケジュールデータを `script_top.js` が `.html()` / `innerHTML` で流し込んでいるなら、データ側のエスケープ（`esc_html` / `esc_attr` / `esc_url`）を必ず確認してください。

**7. `target="_blank"` に `rel="noopener noreferrer"` がない**
外部リンクがすべて該当します。最近のブラウザは noopener を既定にしていますが、旧環境対策とリファラ漏えい防止のため付けておくべきです。

## 低〜確認事項（HTMLからは見えない部分）

**8. セキュリティヘッダー** — ソースには表れないので、レスポンスヘッダーを確認してください。
- `Content-Security-Policy`（インラインスクリプトが多いので nonce 方式を推奨。これが入ると6のXSSの実害も大きく減ります）
- `Strict-Transport-Security`
- `X-Frame-Options: SAMEORIGIN` または CSP `frame-ancestors`（クリックジャッキング対策）
- `X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy`

**9. WordPress運用まわり**
- `/wp-login.php` のレート制限と2段階認証
- `/wp-content/uploads/` のディレクトリリスティング無効化（`Options -Indexes`）
- `wp-config.php`、`.git`、バックアップファイルがWebから見えないか
- Contact Form 7 の送信先に reCAPTCHA/Turnstile 等のスパム対策があるか

**10. 細かい点**
- `og:image` が2回出力されている（セキュリティではなく実装バグ）
- GAのID `G-XXXXXXXXXX` とTypekitの `xxxxxxx` はダミーのまま

## まとめ

優先順位としては **jQuery更新 → xmlrpc無効化 → RESTユーザー列挙の遮断 → バージョン情報の除去とプラグイン更新 → セキュリティヘッダー追加** の順が効果的です。

実機に対して WPScan などで検証したい場合や、CSPのnonce設定・`functions.php` の修正コードが必要であれば、そのまま書き出せます。このレポートをドキュメントとして残したい場合も言ってください。
