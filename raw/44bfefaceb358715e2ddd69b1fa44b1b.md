# a
これはAnthropicのブログ記事（2026年7月24日公開、Thariq Shihipar執筆)で、テーマは「Claude 5世代モデル向けのコンテキストエンジニアリングの新ルール」です。要点をまとめると：

Claude Opus 5やClaude Fable 5のような新しいモデルに対して、Claude Codeのシステムプロンプトの80%以上を削除しても、コーディング評価で測定可能な性能低下はなかったという発見が出発点です。つまり、これまでのモデルには必要だった細かいルールや制約が、新世代モデルではむしろ「足かせ」になっていた、という話です。

記事では「昔の常識 → 今のやり方」という形で6つの変化を挙げています。

1. **ルールを与える → 判断に任せる**：以前は「コメントを書くな」など強い指示で最悪ケースを防いでいたが、新モデルは判断力が向上したため、「周囲のコードに合わせて、コメントの密度・命名・イディオムを揃えて書く」といった緩やかな指針に置き換えたとのこと。

2. **例を与える → インターフェースを設計する**：最新モデルでは、例を与えるとかえって探索空間が制約されることが分かったため、ツールのパラメータ設計自体を表現力豊かにする方が効果的。

3. **全部先頭に詰め込む → 段階的開示（progressive disclosure）**：コードレビューや検証の手順は常時プロンプトに入れず、必要な時だけ読み込むスキルに分離。一部のツールは「遅延読み込み」になっており、エージェントがToolSearchで定義を検索してから使う仕組みで、使うまでコンテキストを消費しない。

4. **繰り返し指示する → ツール説明に一度だけ書く**：昔は指示の重複が必要だったが、今はツールの説明文に書けば十分。

5. **CLAUDE.mdでメモリ管理 → 自動メモリ**：ユーザーが#ホットキーで手動保存する代わりに、Claudeが作業に関連するメモリを自動的に保存するようになった。

6. **シンプルな仕様書 → リッチな参照**：MarkdownのプランよりもHTMLアーティファクト、テストスイート、他コードベースの関数、ルーブリックなど、より高密度な参照を扱えるようになった。

実践面のアドバイスとしては、CLAUDE.mdは軽量に保ち「コードベース内の落とし穴」に集中させること、スキルは過度に制約せずチーム固有の知見を載せること、などが挙げられています。また、`claude doctor`という新コマンド（Claude Code内では/doctor）で、スキルやCLAUDE.mdファイルを適切なサイズに調整できるそうです。

一言でまとめると「新世代モデルは賢くなったので、細かく縛るのをやめて、判断を任せ、必要な情報を必要な時にだけ渡す設計にシフトしよう」という内容ですね。
