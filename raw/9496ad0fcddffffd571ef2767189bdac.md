# バーチャルカード入門 — AI自動決済時代の個人向けガードレール

> 2026年8月時点の情報をもとに整理したメモ。各サービスの仕様(上限・手数料等)は変わりうるので、利用前に公式サイトで最新情報を確認してください。

## 1. バーチャルカードとは

物理カードを発行せず、**カード番号・有効期限・セキュリティコードだけをアプリ上で発行**してネット決済に使う仕組み。決済ネットワーク(Visa / Mastercard)から見れば通常のカード番号なので、EC サイト側は特別な対応なしで受け付けられる。

発展形が**使い捨て(シングルユース)型**で、1回決済に使われると番号が自動的に無効になる。番号が漏れても、その番号では二度と決済できないため、リスクが1回分の取引に限定される。米国では Privacy.com が有名。2026年8月には、xAI の Grok Bot がシングルユース仮想カードを使って Tesla Model Y の購入を自律実行した事例が報じられ、「AIエージェント×使い捨てカード」の組み合わせが現実のものになった。

**クレカとの違いは「番号がカード本体と切り離されていて、作るのも捨てるのも一瞬」という点だけ**で、裏側の決済インフラは同じ。

## 2. 国内で使える主なサービス比較

| サービス | 個人で持てる番号数 | 一番号あたりの主な諸元 | 種別 |
|---|---|---|---|
| **Kyash** | バーチャル1枚(+リアル1枚) | 本人確認済みで1回30万円・月100万円。未確認なら1回3万円・月12万円。発行無料 | プリペイド(Visa) |
| **バンドルカード** | バーチャル1枚(+リアル) | 本人確認なし: 残高上限10万円・1回チャージ3万円・月12万円・累計100万円。リアル+プラス(本人確認あり): 残高100万円・月200万円。発行無料 | プリペイド(Visa) |
| **Vプリカ** | 複数発行可(額面ごとの買い切り型) | 無印は残高上限10万円・チャージ1回3万円・月12万円。バーチャルの有効期限1年。発行無料 | プリペイド(Visa) |
| **PayPay銀行 カードレスVisaデビット** | 最大4番号 | 限度額は0〜200万円の範囲で1万円単位で自分で設定可。年会費無料。別途「ワンタイムデビット」は決済のたびに番号が変わる使い捨て型 | 銀行口座直結デビット |
| **Revolut** | バーチャル最大4枚/30日+使い捨て1枚(+リアル最大6枚) | 使い捨ては無料プランでも利用可。決済後に番号が自動で変わり、旧番号は削除される | プリペイド式 |
| **エポスバーチャルカード** | 本体カードに対し1枚(番号の再発行=変更は可) | 利用可能額を本体カードの枠内で低く設定でき、番号変更もWebで即時 | クレカ紐づけ型 |

ポイント:

- Privacy.com のように数十枚を量産できる米国型サービスは日本には(まだ)ない
- **枚数で分けたい** → PayPay銀行(4番号)、Revolut、Vプリカ(買い足し型)
- **使い捨て(1回で番号が変わる)を使いたい** → Revolut の使い捨てカード、PayPay銀行のワンタイムデビット
- Kyash / バンドルは「チャージした残高しか使えない+アプリで即ロック/番号再発行」で同等の守りを実現するタイプ

## 3. どこでも使えるのか

正規の Visa / Mastercard 番号なので、**オンライン加盟店の単発購入ならほぼクレカ同等に通る**。ただし弱点がある:

1. **サブスク・継続課金**: プリペイド・使い捨て型は登録を拒否されることがある(Revolut の使い捨ては仕様上サブスク不可)
2. **デポジット(仮売上)**: ホテル・レンタカーの保証金には使えない
3. **3Dセキュア必須サイト**: 本人確認未完了アカウントだと通らないことがある
4. **実店舗**: バーチャル単体では不可。Apple Pay / Google Pay に登録できるサービス(Kyash、バンドル等)ならタッチ決済で利用可

→ 「ネット単発購入は◎、サブスクと対面・デポジット系が弱点」と覚えておく。

## 4. 番号が漏れたらどうなる? — リスクモデル

**「カード番号」と「アカウント」は別物**、というのが安全設計の核心。

- カード番号(+有効期限+CVV)は**「残高から支払う」ためだけの出口専用の鍵**
- チャージは、アプリにログインした状態でしかできない操作(入口の鍵は別管理)
- よって番号侵害時の最悪ケースは「**その時点の残高(または設定した限度額)を使い切られる**」まで。気づいたらアプリからロック/番号再発行で即無効化できる
- クレカは番号が漏れるとショッピング枠(数十万〜百万円)まるごとが攻撃対象になるのと対照的

注意点:

- **口座直結デビット(PayPay銀行等)は「残高=銀行口座残高」**。限度額を低く設定しないとプリペイドより被害が大きくなりうる。クレカ紐づけ型(エポス等)も利用可能額を絞るのが前提
- 本当に怖いのは番号侵害ではなく**アカウント乗っ取り**(ログイン情報の漏洩)。この場合はチャージ含め全操作が可能になる。カード番号よりも「アプリのログイン」を固く守るのが正しい優先順位(パスキー/生体認証、パスワード使い回し廃止)

## 5. AI自動決済(Agentic Commerce)への個人の備え

方向性は「**AIに渡す財布を、金額・期間・用途の三方向で小さく区切る**」。

### 今日からできること

- **AI専用の決済レーンを1本作る**: メインのクレカ・銀行口座はAIに渡さない。バーチャルカードをAI用に割り当て、「使う分だけ都度チャージ」運用にすれば被害上限=チャージ額で頭打ち
- **番号を用途で分ける**: 「サブスク用」「単発購入用」「AI用」と番号を分ければ、事故時に1本だけ止めれば済み、漏洩経路の特定も容易
- **決済通知を全部オンにする**: AIの「発注したつもり/してないつもり」のズレを人間が数秒で検知できる、最重要の防御
- **アカウント防御を最優先**: パスキー/生体認証の有効化。チャージ権限を守ることに直結する
- **AI側にも上限を設定**: 「◯円以上は必ず承認を求める」設定を習慣に。Grok の Tesla 購入事例も「明示的なユーザー許可+使い捨てカード」の二段構えだった
- **補償規定を読んでおく**: プリペイド型はクレカより不正利用補償が薄い(または申請期限が短い)ことがある。「AI用の財布は補償が薄い前提で少額運用、大きな買い物は補償の厚いクレカで自分の手で」が現実的な使い分け

### 少し先の動き

決済業界側でも AI エージェント専用の仕組みが標準化されつつある。Visa は「Intelligent Commerce」、Mastercard は「Agent Pay」として、エージェントに本物のカード番号ではなく**利用条件付きの専用トークン**を発行し、「本人が本当に依頼したか」を検証してから決済を通す枠組みを展開中。日本のカード会社にも順次展開される見込みで、今後はメインカード選びの新しい軸になる。それまでの過渡期は、**バーチャルカード+少額チャージ+通知**という手動ガードレールが個人の最善手。
