# q geovisitor（ジオビジター）というゲームを思いついた。

まず範囲（レンジ）を指定する。市町村かその次の番地くらいで。
次に、レンジ内でランダムな場所を選び、そこから最も近いストリートビューの写真を数点ほど取得して提示する。
プレイヤー二人は、物理的にその場所に近づいたら勝ち。つまりGPSと脚を使った遊びになる。

どう？

# a 面白いと思います。
GeoGuessrの「写真から場所を当てる」と、Ingressやオリエンテーリングの「実際に足で行く」を掛け合わせた形で、しかも技術的には Street View の metadata API で「指定座標に最も近いパノラマ」を取れるので、実装のハードルも低いです。日本はストリートビューの網羅率が高いので土壌も良い。

気になる点をいくつか。

**勝敗の公平性** ── 二人の出発地点が違うと、目標が偶然近い側がほぼ勝ってしまいます。同じ地点から同時スタートにするか、「先に到着」ではなく「制限時間内に何m まで近づけたか」で競うほうが読み合いが生まれそうです。目標地点の分からない状態で「こっちの方向っぽい」と推理して動く、という駆け引きが一番の面白さになるので、勝利判定は「半径○m以内」で明確にしておくといいでしょう（GPS 誤差を考えると 20〜30m くらい）。

**住宅街問題** ── 番地レベルでランダムに選ぶと、目標のかなりの割合が普通の住宅の前になります。見知らぬ二人がスマホ片手にうろついて、人の家の前で「着いた！」とやるのは、日本の住宅街だと通報リスクがあります。候補地を公園・駅前・商店街・神社など公共性の高い場所に絞るフィルタがあると安心ですし、ゲームとしても「特徴のある景色」になるので写真からの推理が成立しやすくなります。住宅街の写真は塀と電柱ばかりで手がかりが薄いのが実際のところです。

**チート耐性** ── 写真をそのまま画像検索されたり、レンジが狭ければストリートビューを総当たりされたりします。カジュアルに遊ぶ分には気にしなくていいですが、多少ぼかす・部分切り抜きにする・画像の保存を制限する、あたりは考えどころです。

**安全面** ── 競争で急ぐと信号無視や自転車の暴走が起きるので、「走行中はアプリが位置更新を止める」「移動は徒歩限定」といったルールがあると健全です。

拡張として、レンジ指定を「駅から徒歩圏」「この公園内」のようにできれば、旅行先や飲み会の余興でも使えて、ターゲット層が広がりそうです。
