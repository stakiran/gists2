Cloneして SKILL.md(551行)、anti-patterns、サブパターンカード、scoop-check、評価設計まで読み込みました。「失敗から学んだ跡が明記されているもの」を優先して20個抜き出します。

1. **パターンを「生成テンプレート」ではなく「診断語彙」として使う** — レシピとして逐語実行させる旧設計では「コーパスで検証済みのインクリメンタルな研究」に生成が収束した、と失敗が明記されていて、思考の語彙として読ませる方式に転換している。

2. **anti-patterns は生成時に読ませず、監査時のみロード** — 「リジェクトされやすい組合せ」を生成前に見せるとかえってそれに引っ張られる(Streisand効果)ため、Phase 2は読まず Phase 3.2 の監査だけが参照する。

3. **採択率の統計的priorが設計に入る場所を1箇所に限定** — 歴史的採択率は anti-patterns のリスク重みとしてのみ使い、「禁止ではなくガード」と宣言。しかも閾値(n≥30 かつ Oral率が基準比−12pp以下)と必要な緩和策をセットで文書化している。

4. **監査と修正を別のLLM呼び出しに分離** — 攻撃を提案するLLMと攻撃に答えるLLMを分けることで「自分が答えられる攻撃だけ選ぶ」自己回答バイアスを排除。実装可能性監査も同じ理由で「懐疑的な実装エンジニア」の別ペルソナ・別呼び出し。

5. **判定を「ハードフロア+ソフト判断」の2層に** — 純粋な機械集計は些細な指摘でも revise が過剰発火し、純粋なLLM判定は迎合バイアスと監査証跡の喪失を招く。コーパス由来の事実(Reject パターン一致など)はLLMが覆せないハードフロア、残りは文脈込みのソフト判断。

6. **kill-switch フィールドの構造的保護** — 反証計画と計算予算は Phase 2.2 以降バイト単位同一を要求し、マージャーとアセンブラが該当フィールドへの書き込み自体を拒否する。「LLMがドリフトしないよう覚えておく」契約から「物理的に書けない」契約への転換、と明記。

7. **修正はパッチ形式のみ** — 候補全文をLLMにエコーバックさせる旧契約では約25kトークンの再タイプが実際にタイムアウトを起こした。修正は `applied_revisions[]` パッチ(op語彙: replace / append_sentence / append_items / swap_sub_pattern)で出させ、決定論的なPythonマージャーが適用する。

8. **Phase 4 を skeleton(決定論)→ fill(散文のみLLM)→ assemble(決定論)に3分割** — 約30フィールドの半分は機械的変換(venue引き、group-by、監査からのリフト)なので骨組みを先に決定論で埋め、LLMは `<TODO[path]>` の散文だけ書く。ペイロードが約20k→8kトークン。

9. **コンテキスト規律の明文化** — フルランで180〜250kトークンの中間状態が溜まりタイムアウトする実障害から、「各フェーズは隔離コンテキストで」「成果物はディスクにWrite、チャットにJSONを貼らない」「10KB超の中間ダンプをReadで読み戻すな(以後の全ターンにキャッシュされる)」という具体的ルール3本を規定。

10. **exit code 10/11 のセンチネル・ハンドシェイク** — オーケストレータがLLMを直接呼べない環境では、エラーではなく sentinel ファイル(参照すべきルーブリックの絶対パスと再起動コマンド入り)を書いて終了し、host LLM が作業して再invokeする。Claude Code でも Codex でも cron でも動くハーネス非依存設計。

11. **決定論とLLM判断の境界を意図的に引く** — 検証処理が挟まるステップは全部オーケストレータ化する一方、「catしてLLMに流すだけの薄いラッパーはBashにしない(決定論を買えず脆さだけ足す)」と、あえて自動化しない判断も理由付きで書いてある。

12. **one-shot 保証** — 1入力から必ず「アイデアカード / do_not_generate.md / phase_3_failed.md」の3種のいずれかが出て、途中でユーザーに聞き返さない。欠損情報は推論し、推論不能なら質問ではなく改善手順付きの do_not_generate に落とす。

13. **「生成しない」出口を一級市民として設計** — 関連文献が5本未満、方向が広すぎる、現在の15パターン語彙がカバーしない(ベンチマーク構築等)場合は正直に降りる。カバー範囲外を When NOT to use に明記しているのも同様。

14. **役割ベースの文献検索** — 4コネクタに非重複の時間窓と役割を割り当てる(arXiv=0〜6ヶ月のプレプリント、OpenAlex/S2=6〜24ヶ月の出版済み、OpenReview=0〜6ヶ月の査読中=未来シグナル)。窓が重ならないので同一論文の二重カウントが構造的に起きにくい。

15. **escape-mechanism クエリ** — 問題の語彙で検索すると「すでにそのボトルネックを解決し、解決策の語彙でタイトルを付けた論文」を体系的に取りこぼす。だから検索クエリ4〜6本のうち1本は必ず解決策語彙で作らせる。

16. **全文取得のハードゲート** — 旧版は取得失敗時にアブストのみの推論へ「静かに劣化」するのが失敗モードだった。現在は Phase 1 が fulltext_cache.json の存在で停止条件を張り、部分失敗は degraded フラグ付きで続行。Limitations 節をあえて取得しない(著者の書く limitation は監査が合成するものより弱い)判断も面白い。

17. **決定論的な引用ゲート+意味論的バックストップの層状防御** — サブパターン引用の親子整合はバリデータで機械検証。ただし「親パターンの雰囲気だけで書いて実在のC##を引用する」ズルは機械では捕まらないので、「core_mechanism が本当にそのクラスタ固有の動きを実行しているか」を問う recipe_application_check をLLM側の背後防御として追加した経緯が書かれている。

18. **反証計画に非トートロジー構造を強制** — 負荷を担う変数を1つ名指しし、その変数への介入が「下流の成果指標」をベースラインへ戻すことを negative control として要求。「Xに介入したらXが0になる」は定義の検証でありメカニズムの検証ではない、という却下基準まで明文化。

19. **評価シードのリーク対策** — ICLR 2026 Oral 論文の「タイトルのみ」から問題シードを作り、手法を示す接尾辞や抄録由来の情報を除去、各レコードに leakage_risk と書き換え方法を記録。実在のOral論文を「人間チームの上限アンカー」として対応付けておく設計。

20. **scoop-check の新規性判定を離散化** — 新規性を4軸(問題枠組み/コアメカニズム/鍵洞察/応用領域)の一致数で5段階に機械的に写像し(level = 5 −一致軸数)、モデルの記憶から想起した論文も「自動昇格も自動降格もせず」検索結果と同じ基準で審査。アブスト段階の判定はトリアージであって最終判定ではない、と深掘りでの上方/下方修正を義務化。

次点としては、候補生成をK=3からK=1に減らした判断(下流に自動選択がないので多様性がただのオーバーヘッドだった)、飽和・未検証パターンを避けて中頻度を好む saturation-aware 選択、計画に「週数」ではなく依存関係だけを書かせる(カレンダー予測禁止)、コネクタ劣化時に部分実行をフル実行と誤認させないための CONNECTORS DEGRADED バナー、あたりも良い判断です。全体を貫くテーマは「LLMの規律はプロンプトで頼むのではなく、構造(ファイル分離・パッチ・バリデータ・ロード順序)で強制する」で、これはこのスキルに限らず流用できる教訓だと思います。
