# Mozillaの働き方と制度：詳細分析

作成日：2026年10月16日

## エグゼクティブサマリー

Mozillaの働き方の独自性は、個々の福利厚生ではなく「非営利財団が営利法人を100%所有し、株式報酬を持たず、オープンソースの意思決定様式を社内に残したまま、2005年からリモートで運営してきた」という構造の組み合わせにある。制度面で目立つのは次の5点。

1. 四半期ごとの全社一斉ウェルネスデー
2. 誕生日休暇
3. 米加で出産側26週・非出産側12週の有給育休
4. 本人拠出に関係なく会社が基本給の一定割合を拠出する退職金制度（100%即時ベスティング）
5. 全正社員対象の業績連動ボーナス（株式報酬の代替）

一方で、2020年以降に少なくとも4回の人員削減（最大250人）を経営判断として実施しており、収益の約85%をGoogleとの検索契約（Firefoxの初期検索エンジンをGoogleにする対価として、検索広告収入の一部をGoogleがMozillaに支払う契約）に依存する脆弱性が働き方の安定性を左右している。文化はグリーン、存在目的の置き方はティール、意思決定の実務はオレンジ、という層ごとに色の違う組織であり、「どこを真似るか」を層で分けて考える必要がある。

## 1. 組織の基本構造

### 二層構造

- **Mozilla Foundation**（2003年設立、カリフォルニア州の非営利法人）：Mozillaの商標と知的財産を所有し、プロジェクトのガバナンスと政策を担う。
- **Mozilla Corporation**（2005年8月3日設立、課税対象の営利法人）：Firefox等の製品開発と収益活動を担う。Foundationが100%所有し、利益はすべてMozillaプロジェクトに再投資される。
- 別法人として**MZLA Technologies**（Thunderbird）、**Mozilla.ai**、**Mozilla Ventures**があり、採用窓口もそれぞれ異なる場合がある。

### 働き方への含意

- **株式報酬が構造的に存在しない。** 非上場かつ非営利傘下のため、ストックオプションやRSUで報いる選択肢がない。テック業界の人材競争において、これを「業績連動ボーナス」「手厚い福利厚生」「ミッション」で代替している。
- **存在目的（Mozilla Manifesto）が会社の上位にある。** 株主価値の最大化ではなく「インターネットを開かれた公共資源として守る」ことが法人の目的として明文化されている。
- **収益構造は脆弱。** 2024年の収益約5.7億ドルのうち約85%がGoogleとの検索契約に由来する（CFO Eric Muhlheimの2025年5月の法廷証言）。検索契約とは、Firefoxの初期検索エンジンをGoogleに設定する対価として、Firefox経由の検索で得た広告収入の一部をGoogleがMozillaに還元する取り決めで、AppleのSafariも同様の契約を結んでいる。契約更新や独禁法の動向が、雇用の安定性に直結する。

## 2. リモートファーストの設計

### 歴史的経緯

Mozillaのリモートは、コロナ後に導入した「制度」ではなく、オープンソースから「組織的に進化した結果」である。社員とボランティアのコントリビューターが各地に集まるたびに拠点を開いた結果、チームは創業当初から地理的に分散していた。コロナ以前の時点で約40%の社員がオフィス外で働いていた（2022年10月の公式ブログ）。

### 2022年の「Desire Lines」アプローチ

2022年4月のオフィス再開時、Mozillaは「コロナ前に戻す」「完全出社」「完全リモート」のいずれも選ばず、2022年末までの暫定方針を置いて「社員が実際にどう動くか」を観察する方法をとった。都市計画で歩道を敷く前に人が踏み固めた道（desire lines）を見る手法に倣ったもの。

観察から得た事実：

- 以前オフィス勤務だった社員のうち、週5日出社を望んだのは**6%**。
- ベイエリア在住の社員は2020年初の300人超から**200人未満**に減少。
- サンフランシスコ拠点（100人設計）の日常利用は**8〜10人/日**。

### 現在の設計要素

| 要素 | 内容 |
|---|---|
| 出社義務 | なし（元オフィス勤務者を含む） |
| オフィスの位置づけ | 「集まる場所」。計画、デザインスプリント、ハッカソン等の対面が有効な活動に使う |
| 座席 | 固定席廃止、全面ホテリング（予約制） |
| チームミートアップ | 平均四半期に1回。Employee Experienceチームが参加者の居住地から最適な開催地を選び、旅費・宿泊・食事・学習体験を手配。リモート参加者の包摂も設計 |
| All Hands | 年次の全社集会は対面＋リモートのハイブリッド（2022年はハワイ開催） |
| 全社ミーティング | コロナ期に月次から週次へ変更し、ライブ配信・録画が標準 |
| 採用面接 | 100%リモート（オフィス近隣に住まない候補者の公平性を担保） |
| 早期キャリア社員 | マネージャーとの同一拠点勤務要件を撤廃 |
| 手当 | 自宅インターネット代補助、在宅勤務環境の備品予算（コロナ期に全社員へ拡大） |
| 拠点 | サンフランシスコ、サンマテオ、ベルリン、トロント、ニューヨーク、パリ、ロンドン、タルサ |

### 設計思想として注目すべき点

- **ハイブリッドを「両方の良いとこ取り」と見なしていない。** 公式に「ハイブリッドは望むような最良の両立ではない」と明言し、リモート社員が評価・昇進で不利になる無意識バイアスを問題として認識している。
- **包摂の観点からリモートを守る。** 在宅の恩恵を最も受けるのが育児者や特別な配慮を要する人であり、彼らがテック業界で過小代表であることを根拠に、リモートの制度的保護を正当化している。
- **「製品と同じ方法で働き方を作る」。** テストして適応するという製品開発の方法論を人事制度に適用すると宣言している。

## 3. 休暇とウェルビーイング

| 制度 | 内容 | 適用範囲 |
|---|---|---|
| 祝日 | 国ごとの祝日（米加は12日） | 全社（国別） |
| 有給・病欠 | 入社日から付与開始 | 全社（詳細は国別） |
| 全社ウェルネスデー | 四半期ごとに全社員が同時に休む日。コロナ期の全社ウェルネスブレイクを恒久化したもの | 全社 |
| 誕生日休暇 | 「最も個人的な祝日」として付与 | 全社 |
| 育児休暇 | 出産側26週・非出産側12週の有給 | 米加（他国は現地制度） |
| メンタルヘルス | セラピー、コーチング、アセスメントを健康保険に含む | 全社 |
| ウェルビーイング手当 | 四半期ごと、「自分のためだけに使う」趣旨 | 全社 |

**全社一斉のウェルネスデー**は設計上重要である。個人が取る休暇はリモート環境で「休んでいる間に仕事が溜まる」「取りにくい」という問題を生むが、全社が同時に止まることでその心理的コストを除去している。コロナ期の燃え尽き対策として始まり（2021年のWashington Post報道でも取り上げられた）、定常制度として残った数少ない例の一つ。

## 4. 報酬設計

| 項目 | 内容 |
|---|---|
| 株式報酬 | なし（非上場・非営利傘下のため構造的に不可能） |
| ボーナス | 全正社員を対象とした業績連動ボーナス。「一つのチームとして成功を分かち合う」という位置づけ |
| 退職金 | 米加：本人が拠出するかに関係なく会社が基本給の一定割合を401(k)/RRSPに拠出。100%即時ベスティング |
| 医療 | 米加：医療・歯科・眼科の保険料を100%会社負担。配偶者・ドメスティックパートナー・26歳未満の扶養家族も加入可 |
| 保険 | 生命/AD&D、短期・長期障害保険（地域により異なる） |
| その他 | 社員紹介ボーナス、リモート勤務者のネット代補助、在宅環境の備品予算 |

退職金拠出が「本人の拠出に紐づかない」のは、米国の401(k)で一般的なマッチング方式と異なる。低所得層や拠出余力のない社員にも同じ恩恵が届くため、公平性を意識した設計と読める。

## 5. 学習・成長

- 全社員に**年間の自己啓発予算**。技術・マネジメント研修、資格、カンファレンス等に使える。
- 「やりながら学ぶ（learning by doing）」を基本思想としつつ、役割の外の学びにも投資すると明言。
- 新入社員向けの「文化的オンボーディング」は、2020年にサンフランシスコでの1週間プログラムからバーチャル版に移行。2022年時点で地域別の対面セッション復活を検討。
- 2022年のブログでは「非同期コミュニケーション、会議規律、リモートマネジメントのスキル開発」を今後の投資領域として明示。

## 6. 文化と価値観

### Operating Values（4つの行動価値）

1. **We welcome differences**：多様な視点が良い解決策を生むという理由づけで多様性を位置づける。
2. **We are relationship-minded**：社員同士・ユーザーとの関係を長期で捉え、共感、傾聴、見返りを期待しない貢献を求める。
3. **We practice responsible participation**：透明で開かれたプロセスを「遺伝子の一部」と呼び、入力と出力の両方で寛大かつ親切であることを求める。オープンソースコミュニティ由来の価値観。
4. **We have grit**：巨大企業に挑む困難な仕事をするための楽観、粘り、学習。

### Community Participation Guidelines

社員だけでなくボランティア、イベント参加者、オンラインコミュニティの全員に適用される行動規範。企業の就業規則とコミュニティの行動規範が一本化されている点が、通常の企業と異なる。

### インクルージョン

採用ページに、トランジションを経験した社員、妊娠5か月で採用されたエンジニアなど、個人の踏み込んだストーリーを載せている。性別適合医療を保険でカバーしていることも明記。Diversity Program Managerの職種があり、ERG（従業員リソースグループ）を運営。

## 7. オープンソース由来の意思決定・ガバナンス

Mozillaには企業としての指揮命令系統と並行して、**モジュールオーナー制**という技術ガバナンスが存在する。

- **モジュール**：コードや活動の離散的な単位。すべての重要な仕事はモジュールとして定義されることが理想とされる。
- **オーナー**：モジュールの責任者。**ピア**：オーナーが任命する補佐。
- オーナーはピアを自由に追加・削除でき、モジュール内の判断は原則としてオーナーに委ねられる。
- 全体は「Module Ownership」モジュールのオーナーとピアが監督し、Firefoxについては「Firefox Technical Leadership」モジュールが監督する。
- モジュールの一覧とオーナーは公開されている（firefox-source-docs.mozilla.org/mots）。

働き方への含意：

- **権限の所在が職位ではなく「モジュールの所有」で決まる。** 社員でないボランティアがオーナーになることもあり、逆に社員がモジュール外では決定権を持たない。
- **意思決定が公開の場で行われる。** Bugzillaやガバナンスのニュースグループで議論が可視化され、社外の人も参照・参加できる。
- **社員とボランティアが同じ場で働く。** 2022年のブログでも、コントリビューター（ボランティア）がオフィス開設の契機になったと述べられている。

ただし、このガバナンスが及ぶのは製品・コードの技術判断であり、事業ポートフォリオ、予算、人員といった経営判断は通常の企業と同様にCEOと経営陣が下す。

## 8. フレームワークでの位置づけ

### ラルー『ティール組織』の色分け

| 層 | 色 | 根拠 |
|---|---|---|
| 文化・価値観 | グリーン | 価値観の明文化、インクルージョン、個人のストーリー重視、ウェルネス制度 |
| 存在目的 | ティール寄り | Manifestoが法人の上位にあり、非営利財団が営利法人を所有。「組織は株主のものではなく目的に仕える」構造 |
| 技術ガバナンス | ティール的 | モジュールオーナー制による分散した権限、公開での意思決定 |
| 経営の実務 | オレンジ | CEO・経営陣による事業再編と人員削減、業績連動ボーナス、マネージャーとの1on1 |

ラルー自身も、組織は単一の色ではなく、構造・慣行・文化の各層で色が異なると述べている。Mozillaはその典型例であり、「ティールの三要素（セルフマネジメント、全体性、存在目的）」のうち、存在目的は強く、全体性は文化面で中程度、セルフマネジメントは技術領域に限定されている。

### 他のリモート企業との比較

| 企業 | 共通点 | 相違点 |
|---|---|---|
| GitLab | 全面リモート、非同期、ハンドブック文化 | GitLabは上場企業で株式報酬あり。ハンドブックの網羅性はGitLabが上。Mozillaはオフィス拠点を「集まる場所」として維持 |
| Automattic（WordPress） | オープンソース由来、分散チーム、ミートアップ文化 | Automatticは創業者主導の私企業。Mozillaは財団所有で株式報酬なし |
| Basecamp | 小規模、リモート、カーム志向 | Basecampは少人数の私企業。Mozillaは数百人規模で複数法人 |

Mozillaの独自性は「オープンソースのガバナンスを企業内に残したまま、財団所有という資本構造で運営している」点にあり、リモートそのものはもはや差別化要因ではない。

## 9. 影の部分と限界

### 人員削減の履歴

| 時期 | 対象 | 規模 | 背景 |
|---|---|---|---|
| 2024年11月 | Mozilla Foundation | 約30%（約120人→推定85人） | Advocacy部門とGlobal Programs部門を廃止 |
| 2024年2月 | Mozilla Corporation | 約5%（約60人） | 新CEO Laura Chambers就任直後。VPN、Relay、Online Footprint Scrubber、mozilla.socialを縮小 |
| 2020年8月 | Mozilla Corporation | 約250人（全体の約1/4）＋60人の部署異動 | コロナによる収益減。台北拠点を閉鎖 |
| 2020年1月 | Mozilla Corporation | 約70人 | 新製品の収益化の遅れ |

### 構造的リスク

- **収益の集中。** 約85%がGoogle検索契約由来。2025年の米国独禁法訴訟（Google対DOJ）で検索契約が制限されれば、Mozillaの雇用基盤が直接影響を受ける。
- **経営判断の集中。** 技術ガバナンスは分散しているが、事業の存廃と人員の判断は少数の経営陣に集中しており、2024年の削減はCEO交代から1週間で発表された。
- **日本からの距離。** 2017年にMozilla Japanが独立（現WebDINO Japan）して以降、日本に雇用主体がない。2020年には台北拠点も閉鎖し、アジアの拠点は消滅。
- **採用ページと実態の乖離。** 採用ページは組織の自己像であり、Glassdoor等の口コミや人員削減の履歴と合わせて読む必要がある。

## 10. 日本企業・外資系企業への示唆

### 移植しやすいもの

- **全社一斉のウェルネスデー。** 個人の有給取得率に頼らず、組織全体を止める設計。日本の「有給が取りにくい」文化への対処として有効。
- **誕生日休暇。** 低コストで象徴性が高い。
- **オフィスの「集まる場所」化とホテリング。** 固定席を廃し、チームミートアップの手配を専門部署が担う運用は、日本の中規模企業でも再現可能。
- **Desire Linesアプローチ。** 制度を決め打ちせず、暫定方針で観察してから確定する方法論。
- **退職金拠出を本人拠出に紐づけない設計。** 日本の企業型DC（マッチング拠出）の設計議論に示唆がある。
- **採用面接の100%リモート化。** 地方・海外の候補者の公平性を担保する手段として明示的に位置づける。

### 移植が難しいもの

- **株式報酬なしの報酬体系。** 上場企業や外資系では株式報酬が前提であり、ミッションで代替する前提条件（非営利所有、明文化された存在目的）がない。
- **モジュールオーナー制。** オープンソースの歴史と社外コントリビューターの存在が前提。閉じた企業内で権限の所在を職位から切り離すのは困難。
- **ハイブリッドの限界を公言すること。** 「ハイブリッドは最良の両立ではない」と公式に言い切る姿勢は、出社回帰を進める多くの企業と正反対。

### 議論の論点

- Mozillaの制度は「ミッションによる報酬代替」の実験として読むことができる。株式報酬なしでテック人材を確保できるかどうかは、Googleへの収益依存と人員削減の履歴を見る限り、まだ結論が出ていない。
- リモートファーストの先進性と、トップダウンの人員削減が同居している点は、「働き方の自由度」と「雇用の安定性」が別の軸であることを示す。
