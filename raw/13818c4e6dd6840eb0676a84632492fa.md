# https://claude.dev/blog/solving-code-review-at-anthropic/ 全体の流れがわからんので、もう一度まとめて

# a
一つの変更が「エンジニアの手元」から「ユーザーの手元」に届くまでを、時間順に追います。登場人物はエージェント（Claude）、人間、自動チェックの3つだけです。

### ① 書く・自分で検証する（PRを出す前）

人間がClaudeに「この機能を作って」と指示する。Claudeがコードを書き、テスト・ビルド・リンターを自分で実行して結果を見せる。別のClaude（サブエージェント）が、まっさらな状態でそのdiffを読んでレビューする。ここで大半の凡ミスが直る。**まだPRは存在しない。人間は誰も読んでいない。**

### ② PRを開く → 自動チェックが一斉に走る

PRを開いた瞬間に、4種類のチェックが自動で走る。

- **CI**：lint、型チェック、各OSでのテスト、ビルド。赤ならマージ不可。
- **AIコードレビュー**：複数のClaudeが並列でバグを探す → 別のClaude群が「本当にバグか」投票 → 合意されたものだけがコメントとして投稿される。
- **セキュリティレビュー**：別枠で走る。
- **リスク分類**：分類器が変更内容を読んで「低／中／高リスク」を判定し、人間の承認が何人必要か決める。

### ③ 指摘を潰す

AIレビューとセキュリティレビューの指摘は、**全部に答えないとマージできない**。直すか、「これは意図的」と理由を書いてスレッドを閉じるか。夜間にエージェントが修正を積むこともあり、作者が朝来たらもう一周回っている。ラウンドは3回まで、それ以降は「やり方を見直して」と止められる。

### ④ 人間が承認する（必要な場合だけ）

- 低リスク（文言修正、フラグ裏の追加）→ 人間ゼロでOK
- 中リスク（普通の機能、キャッシュ、自動更新）→ 1人
- 高リスク（課金、CI設定など）→ 2人

エージェントに指示した人が「1人目」としてカウントされる。ボットの承認は人間の代わりにならない。新しいコミットが積まれたら承認はやり直し。

### ⑤ マージキュー

最新のmainにこの変更を乗せた状態で、もう一度全チェックを走らせる。別々に通った2つのPRが合わさって壊れる事故を防ぐ。通ればマージ。

### ⑥ 段階的に公開

まずフィーチャーフラグの裏で**Anthropic社員だけ**が使う。問題なければ`latest`チャンネル、さらに遅れて`stable`チャンネルへ。

### ⑦ 見張る・戻す

作者とオンコール担当がダッシュボードを監視。おかしければフラグをオフ（デプロイ不要）、ひどければリバート。起きた障害は**①〜⑥のどの層が捕まえるべきだったか**を振り返り、その障害PRを評価セットに追加してAIレビュアーを鍛える。

---

### 全体像を一言で

```
人間が指示 → Claudeが書いて自己検証 → PR → 自動チェック群（CI/AIレビュー/セキュリティ/リスク判定）
→ 指摘を全部潰す → リスクに応じて人間0〜2人が承認 → マージキュー → 社内→latest→stable
→ 監視して即ロールバック → 障害はAIレビュアーの教材に
```

「人間が全部読む」の代わりに、**薄いチェックを何層も重ねて、すり抜けても数分で戻せる**ようにしているのがこの仕組みの骨格です。
