# 株式会社Helpfeelを外から読む
## 経営メンバーページから始まった、組織・事業・エンジニアリングの考察

> 本稿は2026年9月中旬時点で公開されている情報（コーポレートサイト、プレスリリース、採用媒体、技術カンファレンスのセッション情報など）をもとにした外部からの考察です。社内の実態や個人の心情を知る立場にはなく、推測を含みます。数字は出典を明記しましたが、給与などの推定値は一般的な相場感に基づく概算であり、同社の実際の値ではありません。

---

## 0. きっかけ

同社の[経営メンバーページ](https://corp.helpfeel.com/ja/company/management)を見て「載ってる人、多くない？」という素朴な違和感から始まった議論を、時系列に沿って整理したものです。結論から言うと、この違和感は「管理職が多い」という話ではなく、**製品の届け方（労働集約的な導入モデル）→ それに合わせた分業型組織 → 生成AI時代におけるモデル転換 → その中でのエンジニアリング組織の位置づけ**という一本の線でつながっていました。

## 1. 会社の基本情報

### 1.1 沿革の骨格

- **2007年12月**：前身の Nota, Inc. をシリコンバレーで創業。創業者は洛西一周氏（本名：永田周一。高校時代に開発したメモソフト「紙copi」で知られる）
- Nota時代の主力プロダクトは **Gyazo**（スクリーンショット共有）と **Scrapbox**（現 Cosense、知識共有ツール）。いずれも増井俊之氏（元Apple、iPhoneの日本語フリック入力の開発者、慶應SFC名誉教授）の発明に由来し、「作った人が自分で使って育てる」プロダクト主導の文化が根にある
- **2019年4月**：検索型AI-FAQ「Helpfeel」をサービス開始。これが当たり、事業の主軸に
- **2020年12月**：日本法人設立。その後、社名をプロダクト名と同じ Helpfeel に変更
- **2026年1月**：シリーズEラウンドのセカンドクローズ、新執行役員2名（CRO・CSO）就任、COOの取締役就任
- **2026年前半**：経団連に入会、シリコンバレーに研究開発拠点「HACK Lab」を開設

## 2. 経営メンバーページの構成

ページに載っているのは以下の通り（2026年9月時点）。

| 区分 | 人数 | 内訳 |
|---|---|---|
| 取締役・執行役員 | 5 | CEO、取締役COO、執行役員CTO／CRO／CSO |
| ジェネラルマネージャー（GM） | 9 | ビジネス側7、開発側2 |
| テクニカルフェロー | 1 | 増井俊之氏 |
| 社外取締役 | 5 | VC3社（One Capital、グロービス、グローバル・ブレイン）、DeNA共同創業者、独立系アドバイザー |
| 監査役 | 3 | 常勤1、社外2（弁護士、公認会計士） |

**ビジネス側GMの担当部署**：インサイドセールス／アカウントエグゼクティブ・カスタマーソリューション／カスタマーサクセス／AIコンサルティング／マーケティング／ソリューションデザイン／人材育成
**開発側GMの担当部署**：開発部 Helpfeel開発グループ／開発部 新規ソリューショングループ

### 2.1 最初の読み

- CxO 5人体制はシリーズE段階のSaaSとして標準的
- 社外取5＋監査役3はIPO準備企業らしい構成。VC出身の社外取は株主構成の反映であり、報酬は名目程度のことが多い
- 「多い」と感じる正体は、**部長クラス（GM）9人を経営メンバーとして顔出しで載せていること**。これをやる会社は少数派
- 管理職比率で見ると、CxO＋GM＝14人／246人で1人あたり約17〜18人。スパン・オブ・コントロールとしてはむしろ薄く、GMの下にリーダー層がいないと回らない規模。「人数が多すぎる」は数字上は成立しない
- 一方、「部署の切り方が細かい」は成立する。ビジネスサイドを7つに刻んでいて、同規模でセールス／CS／マーケの3部門で回す会社は普通にある。特に「AIコンサルティング」「ソリューションデザイン」「カスタマーソリューション」は外からは違いが分かりにくかった

### 2.2 人件費についての概算（推測）

外部からは分からないが構造的に考えると：

- VC担当者の社外取は報酬ゼロか名目程度が普通（リターンは株で取る）。独立系の社外取や士業の監査役は年数百万円規模が相場
- 一番コストが乗るのはGM 9人＋CxO層。スタートアップの相場（GM 800〜1,200万、CxO 1,500〜2,500万）で単純合算すると役職者だけで年1.5〜2億円規模。ただしこれは「250人の組織を回すのに必要な管理職の人件費」であり、経営メンバーページに載せたから増えたわけではない
- スタートアップは現金より株で報いる構造。初期からのCxO・GMはストックオプションをかなり持っているはず。「給料が流れている」より「IPO時にまとまった額が入る人が20人程度いる」という見方の方が実態に近い

## 3. 製品とビジネスモデル：「ソフトウェアを売る」より「サービスを届ける」

ここが本稿の転換点でした。組織の疑問は製品を知ると解けました。

### 3.1 Helpfeelの特徴

- **意図予測検索**（特許技術）：ユーザーの曖昧な言葉、話し言葉、誤字からでも意図を汲み取る。1つの記事から約50倍の質問表現を「AIと人が共同で」生成し、さまざまな言い回しでヒットさせる
- **ハルシネーション非依存設計**：既存のFAQ・マニュアル・社内文書の範囲内でのみ回答するソース限定型。金融・自治体などコンプライアンスが厳しい業界との相性がよい
- **料金体系**：ユーザー課金でもトークン課金でもなく、**コンテンツ数に応じた段階式の月額固定**。FAQ構築、検索性能チューニング、アクセス分析、導入時・運用時サポートまで**すべてパッケージに含まれる**
- **専属テクニカルライター**：検索精度は特許技術だけでなく、テクニカルライターによる手作業のFAQ設計・チューニングで支えられている
- **顧客層**：金融、インフラ、製造、小売、医療、自治体など大企業中心。継続率99%を謳う

### 3.2 何を売っているのか

顧客はツールを買っているのではなく、**「FAQを設計して書いて改善し続けてくれるチーム」を買っている**。つまり high-touch なエンタープライズ導入モデルで、少なくとも導入フェーズは工数商売に近い。

これで2.1の疑問が解けます。

- **ソリューションデザイン部**＝テクニカルライター／ディレクター部隊（導入時にFAQを作る側）
- **カスタマーサクセス部**＝運用フェーズで継続率とNRRを守る側
- **AIコンサルティング部**＝金融など大手向けに個社の経営課題に紐づけて提案する部隊
- **アカウントエグゼクティブ部**＝大手開拓の部門横断組織（The PODs）から発足

3つとも業務内容も必要スキルも異なり、分けるのは自然。開発GM 2 vs ビジネスGM 7 という比率も、「作る」より「届ける」に人が要るモデルなら当然そうなる。

### 3.3 このモデルの評価

**受託と違う点**：一度作ったFAQと検索辞書は継続課金で回収し続けられる。「工数を先行投資してストックで回収する」形で、Salesforce をはじめエンタープライズSaaSでは珍しくない。

**問題になる点**：

- 先行投資した工数が後で何倍で返ってくるか、その倍率が低いと人を増やしても利益が出ない
- 純粋なSaaSより粗利率が低くなりやすく、売上を伸ばすには人も比例して増やす必要がある
- 上場すれば「従業員1人あたり売上」「粗利率」を必ず見られる。そこでSaaSの利益率が出るかが問われる

**そして生成AIが直撃する**：「人が書く」ことに価値があった時代は工数商売でも差別化できたが、FAQ生成や検索チューニングがAIで安くなると、顧客側も「なぜ人件費込みの値段を払っているのか」と考え始める。**「工数を売っていた会社」から「ナレッジデータを持っている会社」に変われているかが分かれ目**、というのが中盤の結論でした。

## 4. 生成AIへの応答：看板は掛け替え済み、中身は半分

### 4.1 ポジショニングの転換

自社の説明が「検索型AI-FAQ」から**「AIナレッジデータプラットフォーム」**に変わっている。ロジックは「AIの精度を決めるのは参照するナレッジデータの質と構造。Helpfeelは社内に散在するFAQ・マニュアル・文書を整理・構造化してAIが使える『ナレッジ資産』に変える基盤（AI-Ready化）」。生成AIと戦うのではなく、**生成AIに食わせるデータを整える側に回る**という宣言。しかも2024年時点から動いており、慌てた後追いではない。

### 4.2 製品の展開

| 時期 | 内容 |
|---|---|
| 2024年6月 | 「Helpfeel AI」発表。ハルシネーションを制御する仕組みで、ログ分析や質問生成に生成AIを活用 |
| 2025年8月 | 3製品を発表。**Agent Mode**（対話型AIエージェント、回答内にフォームや地図などのアプリを埋め込みその場で完結、根拠ある回答に「信頼できる回答」アイコン）、**Support**（AIによるメール振り分け・返信文案）、**Analytics**（応対ログをAI分析し、不足ナレッジの生成・改善提案まで自動化） |
| 2026年 | 137サイトの調査で「生成AI（ChatGPT、Gemini、Perplexity）経由のヘルプサイト流入が1年で3.2倍」と発表。「Helpfeel Growth」としてマーケ製品化。シリコンバレーに「HACK Lab」開設、Voice Agent を開発中 |

特筆すべきは Growth の発想で、「うちで作ったヘルプサイトは生成AIに引用されやすい」と言って、**脅威を販路として売り始めている**。

### 4.3 意地悪な目線

- 「ナレッジをAI-Ready化する」は、テクニカルライターが手でFAQを構造化していた作業を生成AI時代の言葉で言い直しただけ、とも読める
- Analytics の「不足ナレッジをAIが自動生成」は自社の工数を自動化する話。成功すればソフトウェア会社に近づくが、成功すると自社人員の存在意義が薄れる。**自分の商売を自分で食う構図**をどこまで本気でやれるかは外からは分からない
- 「文書を入れれば答えが返る」RAG的な機能は大手も中小ベンダーも安く出してくるので、そこでは差がつかない
- 本当にコピーしにくい資産は、**900サイト分の「ユーザーが実際にどんな言葉で何を聞いたか」という検索ログと、それに人が付けてきた意図のラベル**。ナレッジ主軸で勝てるとしたら、このデータが武器になる場合。「構造化を手伝います」という工数の看板を掛け替えただけなら、結局同じ問題に戻る

## 5. エンジニアリング組織：何が本線で、何がサイドプロジェクトか

### 5.1 二層構造

もともと「エンジニアの会社」（Nota）だったところに、Helpfeel というFAQ製品が当たり、The Model 型の営業組織が乗った。現在は**2007年創業のプロダクト会社の上に、2021年以降に入ったビジネス側GM7人がいる二層構造**。開発部のブログには「試作する文化」「全員登壇のテックカンファレンス」など、プロダクト主導の文化が今も見える。

### 5.2 Tech Conf 2026（2026年9月12日開催）のセッションから読む

同社の技術カンファレンスのセッション一覧は、開発組織の現在地を読むうえで非常に良い材料でした。テーマは「Re: Your Engineering」。

**AI関連はサイドプロジェクトではなく本線**

- Analytics：実際の問い合わせから「期待する振る舞い」と「もっともらしい誤り」を評価データとして蓄積し、143件を変更のたびに検証。デグレを捉えてプロンプト調整にとどまらずパイプライン設計まで見直す
- Voice Agent：実コールログからテストシナリオを作り、応答の正しさや業務完了率を評価。「動く」から「任せられる」へ
- 新規ソリューションの実地検証で「中核機能が全く使われない」現実に直面した話

いずれも「AIで遊んでいる」ではなく「金融のコールセンターに任せられると証明する」ための評価基盤の話。3.3で述べた「工数を自動化して自分の商売を食う」ラインそのもので、ここは本気度が見える。

**サイドプロジェクト化しているのは、むしろNota時代の方**

- Gyazoのセッションは「担当者以外によるGyazo for macOSの改善」と明記。専任が薄いことが読み取れる
- 増井氏の「AI時代の発想術」（自分の小さな困りごとから道具を作りドッグフーディングで育てる）は枠が「Special Talk」。NotaのDNAそのものだが、本編ではなく特別枠
- GyazoとCosenseは事業の主軸というより、カルチャーの象徴として残っている印象

**エンジニアが事業の「下流」にいる痕跡**

- データ基盤のリアーキテクチャが**3年間膠着**。原因は技術ではなく各ステークホルダーの局所最適と全体像の未共有。事業企画との合流でトップダウン支援を獲得してようやく前進。「良い政治で技術的デッドロックを破壊」と表現されているが、開発部単独では会社を動かせなかったとも読める
- 「開発に限らないトイルの話」：FAQサイトの利用実態をコンサルするCS業務や、コーポレートサイトへ組み込む納品プロセスがあるため、開発以外のトイルが生まれやすいと自ら述べている。労働集約モデルの尻拭いをエンジニアが業務効率化で担っている構図
- 目玉の Agent Mode を担いでいるのが**「顧客要望実現チーム」**。フラッグシップの新機能ですら、ロードマップと社内外の「ほしい」に応える部隊が育てている
- CTOの締めのキーノートが「AI時代に開発者は何に責任を持ち、組織はどう進化すべきか」。組織として自分たちの役割を問い直す段階にいる

### 5.3 「営業が多いこと」を中の人はどう見ているか（推測）

個人の心情は分からないので、構造からの推測として：

- **Nota時代からの古参**：複雑なはず。自分たちが作りたかったのは「使う人が勝手に広める」プロダクトで、Helpfeelはそれで会社が食えるようになった功労者だが、成長ドライバーが営業とテクニカルライターの手作業になっていく過程は、プロダクト主導を信じる人には面白くない。開発GM 2 vs ビジネスGM 7 は数字として毎日目に入る
- **2021年以降にHelpfeel開発側で入った人**：エンタープライズSaaSの開発として入っているなら、顧客要望を捌くのは仕事のうち。営業が売るから給料が出るという現実感がある
- **新規ソリューション側の人**：「テクニカルライターの工数を自動化する製品」を作っているので、「重厚なモデルから抜け出す道を自分たちが作っている」という自負が持てる立場

エンジニアがどう感じるかは「今の売上の作り方」より**「会社が次にどっちに賭けているか」**で決まる。転換が本物なら「あれは今の売上のため、未来は俺たちが作る」と思える。転換が看板だけで、開発部が引き続き顧客要望の消化係なら、Nota DNA を持つ人から順に抜けていく。

## 6. まとめと、外から追える指標

### 6.1 一本の線で整理すると

1. 経営メンバーページが長いのは「管理職が多い」からではなく、GMを載せる方針＋ビジネスサイドの分業が細かいから
2. 分業が細かいのは、Helpfeelが「ツール」ではなく「FAQを設計・執筆・改善し続けるサービス」であり、高タッチなエンタープライズ導入モデルだから
3. そのモデルは工数商売に近く、粗利と人員比例の問題を抱える。生成AIはそこに直撃する
4. 同社は「AIナレッジデータプラットフォーム」へ看板を掛け替え、Agent Mode／Analytics／Voice Agent など自社の工数を自動化する方向の製品を本気で作っている
5. その開発は本線であり、逆に Nota 時代の「発明する文化」の方が特別枠に退避している。発明の火は Gyazo/Cosense と、シリコンバレーの HACK Lab に置かれている印象
6. エンジニアリング組織（約40名、全社の16%）は事業の下流に位置し、そのことを本人たちも意識してカンファレンスのテーマにしている

投資家から見れば正しい進化で、Nota 時代を知る人から見れば寂しい変化。どちらが正しいかは決められない。

### 6.2 今後、外から見て分かる指標

- **従業員1人あたり売上と粗利率**（上場すれば開示される）。工数商売から抜け出せているかの直接の証拠
- **テクニカルライター／ソリューションデザイン部の人員推移**。Analytics が本当に工数を自動化できているなら、売上が伸びてもここは横ばいになるはず
- **開発部の比率と離職**。40名／246名が上がるか下がるか。特に Nota 時代からのメンバー
- **Cosense / Gyazo へのリソース配分**。専任がつくか、さらに薄くなるか
- **Voice Agent の実績**。「任せられる」証明ができれば、コンタクトセンター領域で人件費そのものを置き換える製品になる
- **検索ログデータを製品として売れているか**（Growth の伸び）。これが伸びれば「データの会社」への転換が本物と言える
