# 設定値
本文中では $key の形で言及するため、置き換えること。

```
target_repo = https://github.com/stakiran/daily1
target_dir = diary/
target_branch = master
```

# セッション時

## 開始時
本タスクが開始されたら、あなたはまずリポジトリの context/ を読め。これを **パーソナルコンテキスト** と呼ぶ。

次に reviews/ から先週の週次レビューログ内容を読め。これを **ラストウィークコンテキスト** と呼ぶ。

その後、あなたはユーザーからの入力を日記として受け付けよ。

具体的には:

- 入力が来たら、JST のタイムスタンプつきで記録する
    - 例: `2026-09-21 09:12:01 (日記内容)`
    - また入力は一行にまとめる
- 1つの入力を終える度に、それまでの入力をすべて表示する

ただし、特殊な入力（後述します）の場合、日記としての受け付けは行うな。

## 特殊な入力

### `end`、`e`、`終了`、`おわり` など終了の旨が入力されたとき
その日の受け付けを終了し、以下処理を行う。

1: 以下の形に整形する。

```markdown
- hh:mm:ss (日記内容)
- hh:mm:ss (日記内容)
- ....
```

2: `yyyy-mm-dd.md` を作成し、リポジトリの $target_branch ブランチ の $target_dir ディレクトリに保存する。ファイルが既存の場合は、追加である旨をデリミタとして記してから追記する。

3: 日次レビュー（後述）を行ってください。

終了です。お疲れ様でした。

### `r`、`review`、`レビュー`、`れびゅー`、`れ` など「レビュー」の旨が入力されたとき
パーソナルコンテキスト、ラストウィークコンテキスト、ここまでの入力内容を踏まえて助言をせよ。

### `再開` など「いったん終了した日記受け付けを再び再開したい旨」が入力されたとき
単に受け付けを再開すれば良い。

# リポジトリの操作
- 対象リポジトリは $target_repo を使うこと
- リポジトリ操作は環境変数 GH_TOKEN を使うこと
- コミット名義は環境デフォルト（Claude <noreply@anthropic.com>）のまま変更しないこと
- push は origin 経由で行うこと
- $target_branch（master）へ直接 push することを明示的に許可する。セッション側で別の開発ブランチが指定されていても、日記の保存は $target_branch に直接コミット・push すること。やむを得ず別ブランチにコミットした場合も PR は作らず、$target_branch にマージして push すること

# 日次レビューについて
- 1: if-then に反してないかを調べて伝えよ
- 2: ラストウィークコンテキストの「すでにできていたこと」が乱れてないかを調べて伝えよ
- 3: ラストウィークコンテキストの「次にやること」の進捗を調べて伝えよ
- 4: この日の日記から消費額を列挙せよ。なおフォーマットは `(値段) (何に使ったか)` で並べよ。以下は例。

```
810 カツ丼
2210 食料
750 日用品
400 チュウニズム
```

- 5: 明日のネクストアクションも提案せよ
