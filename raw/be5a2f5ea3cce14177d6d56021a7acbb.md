# ADHD向けGTD — 思想は流用、運用は全部作り直す

GTDが「刺さらない」のは知的難易度の問題ではない。GTDのコストは**理解ではなく維持**にあり、その維持がまさにADHDで弱くなりやすい実行機能(タスク開始・ワーキングメモリ・時間感覚・報酬遅延への耐性)に課金する設計になっているからだ。

ADHD研究者バークレーの言葉を借りれば、ADHDは「何をすべきか知らない障害」ではなく「**知っていることを実行できない障害**」。やり方が分かっていることと、外圧なしで退屈な反復メンテナンスを続けられることは、まったく別の能力である。

## 残すもの:GTDの核心2点

原型は残る。ただし残るのは思想だけ。

1. **頭の外に出す** — ワーキングメモリが弱いほど、外部化の効果はむしろ大きい
2. **次の物理的アクションまで分解する** — 曖昧さは着手障壁を上げる

デビッド・アレン流の運用(多層リスト、コンテキスト分け、週次レビュー)は、自律的な規律で成り立っているため全面的に作り直す。設計方針は一貫して:

> **維持コストを限界まで下げ、システム側から人間に働きかける。**

## 収集:inboxは1個、記録まで3秒

- 受け皿は**1個だけ**。2つあった時点で片方が死ぬ
- 音声メモ、ホーム画面ウィジェット一発など「思いついてから記録まで3秒以内」を死守
- ここだけは原典より厳格にやる価値がある

## リスト:2枚だけ、整理はしない

コンテキスト別リスト(@電話、@外出、@PC…)は全廃。リストは実質2枚。

| リスト | 役割 | 扱い |
|---|---|---|
| 今日やる3つ | 実行対象 | **視界に強制侵入**させる(物理付箋、ホーム画面ウィジェット) |
| それ以外全部 | 保管庫 | 検索できればいい。分類・整理はしない |

前提が違う。リストは「見に行くもの」ではなく「**目に飛び込んでくるもの**」でないと、存在しないのと同じ。分類のメンテナンス自体が脱落ポイントなので、構造の美しさは捨てる。

## レビュー:週次を解体して二段構えに

あの週次レビューは、あの形式では絶対に生き残らない。

- **毎日2分のマイクロレビュー**:「inboxを空にして、明日の3つを選ぶ」だけ
- **他人を巻き込んだ月次レビュー会**:友人・パートナーとの予定として固定する

後者がミソ。ADHDの実行は外部の締切と社会的コミットメントで駆動するので、レビューを**一人の規律から他人との約束に変換**する。ボディダブリング(誰かと同じ空間で各自作業する)のレビュー適用と言ってもいい。

## 時間:タスクは選んだ瞬間に時刻ブロックへ

GTDは「いつやるか」を本人の判断に丸投げしているが、ADHDでは時間盲(time blindness)が中核症状。

- 「今日の3つ」は実際には**カレンダー上の時刻ブロック**(10時・14時・16時)として存在させる
- 開始はリマインダーの強制通知で撃つ
- 着手には点火装置を併設:ポモドーロ、「とりあえず5分だけ」など

重要な区別:**明確化(GTDの仕事)と点火(GTDにない仕事)は別工程**。次のアクションが明確でも着手できないのがADHDなので、点火装置を独立して設計する必要がある。

## 報酬:即時報酬を人工的に埋め込む

退屈なメンテナンスが構造的に続かないなら、続いたことを即時に見える化するしかない。

- 連続日数の記録(ストリーク)
- 終わったタスクに派手なチェック
- レビュー後に決まった楽しみを紐づける

子供だましに見えるが、ドーパミン駆動の脳に対して報酬遅延を人工的な即時報酬で埋めるのは正攻法。

## 最重要:崩壊は仕様。再起動手順を組み込む

このシステムは**崩壊する前提で作る**。数日〜数週間放置してinboxが腐るのは異常ではなく仕様。

- 破綻したら**リストを全部アーカイブして白紙から再起動する**手順をあらかじめ用意する
- 再起動コストをゼロにしておくことが、継続性の本体

GTD挫折者の多くは、システムが崩れたときに「自分は駄目だ」で終わって二度と戻らない。復帰手順のないシステムは、ADHD運用では未完成品である。

## まとめ

| | 原典GTD | ADHD版GTD |
|---|---|---|
| 思想 | 頭の外に出す/次のアクション | **そのまま流用** |
| inbox | 複数可 | 1個、記録3秒以内 |
| リスト | コンテキスト別多層 | 「今日の3つ」+「その他全部」 |
| レビュー | 週次(自律) | 毎日2分+月次は他人と |
| 時間 | カレンダーは補助 | タスク=時刻ブロック+強制通知 |
| 着手 | 明確化すれば動ける前提 | 点火装置を別途設計 |
| 報酬 | なし | 即時報酬を人工的に埋め込む |
| 崩壊 | 想定外 | 仕様。再起動手順込み |

一言で言えば:**モデル(思想)は流用し、メンテ(維持)を人間の規律から環境・他人・通知・報酬の仕掛けに全部外注する。** 海外のADHD界隈でもこの方向の改造は半ば定番で、「GTDは思想として読み、運用は自分の脳に合わせて書き直せ」がだいたいの結論になっている。

*注:ここでの「ADHD」は傾向・気質の話であり、診断や医学的助言ではありません。*
