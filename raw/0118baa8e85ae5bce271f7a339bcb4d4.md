# USBランプ（通知用インジケータライト）の市場調査メモ

> コマンドから点灯させるUSB接続ランプを作れないか、という着想からの調査ログ。
> 結論から言うと **カテゴリは既に存在するが、現行の王者が停滞していて、日本には正規販売がない**。

---

## 1. 作ろうとしていたもの

- USB接続のランプ。コマンドを叩くと点灯する
- 主用途はスケジュール実行（指定時刻に光る）と通知連携（イベントが来たら光る）
- `n秒点灯` はオプション指定
- ランプ側にハード的な制御機構は持たない。暴走したらケーブルごと抜けばよい、という割り切り

想定ユーザー像は「ライフハッカーが通知手段のひとつとして1個挿しておく」イメージ。

---

## 2. 結論

**需要はある。ただし新規カテゴリではない。**

同じコンセプトの製品が2012年から存在し、しかも売り文句がほぼ同一。
勝負するなら「発明」ではなく「停滞している先行製品の後継を取りに行く」フレームで考えるべき。

---

## 3. 既存製品

### blink(1) / ThingM — 本命の先行例

想定していたものと、ほぼ同一のコンセプト。

- 2012年 Kickstarter 発。現行は mk3
- 公式コピーが「IFTTT・メール・URL・自作スクリプトに繋げて、画面を見張らずに状況を一目で知るための小さなUSBライト」
- CLI ツール `blink1-tool` あり
- 公式ライブラリ: Python / Node.js / Java / Rust / Go / Android
- Linux カーネルに制御機能が入っている
- CI 連携事例が公式 FAQ に掲載（Travis / GitLab CI / TeamCity）
- OSHWA 認証のオープンソースハードウェア

- 製品サイト: https://blink1.thingm.com/
- GitHub: https://github.com/todbot/blink1

## 4. 市場規模の目安

blink(1) 公式によれば、最量販モデルの mk2 が **累計で数万台**。

Kickstarter の話題性、メディア露出、10年以上の販売期間、充実した OSS エコシステム。
それらを全部使って累計数万台 = **年あたり数千台規模**。

これがこのカテゴリの実測値に近い天井と考えるのが妥当。

- 個人の趣味 / ポートフォリオとしては十分すぎる
- 事業として食っていくには小さすぎる

---

## 5. それでも余地がある理由

### カテゴリ自体の強み（スマート電球に対して）

1. **クラウド不要・設定ゼロ・オフライン動作**
   スマート電球の最大の弱点。閉域網の社内、工場、セキュリティ要件の厳しい現場では「Wi-Fi設定もアカウントも不要」が本当に効く
2. **レイテンシ**
   USB は即時。クラウド経由は1〜3秒かかる。ポモドーロや時報系の用途では体感が明確に違う
3. **認証コストの低さ**
   無線を積まないので技適不要。USB バスパワーなら PSE も基本かからない。個人でハードを出すなら身軽さが大きい

### 先行製品側の隙

- ThingM のサイトのニュースが 2021〜2022 年で止まっているように見える
- 販路が Amazon / getDigital.de（EU）/ インド代理店。**日本の正規取扱が見当たらず、個人輸入するしかない**
- Blink1Control2 は Electron 製 GUI。2026年の開発者体験としては古い

→ 空いているのは「発明の余地」ではなく **「後継の余地」**。
カテゴリを作る話ではなく、10年前の製品が停滞している椅子に座る話。
勝ち筋としてはむしろ健全。誰も欲しがらないものを作るより、欲しがる人がいると実証済みのものを作り直すほうがずっと楽。

## 7. 設計上の指摘

### ウォッチドッグは入れるべき

「暴走したらケーブルを抜けばよい」という割り切り自体は妥当。
ただし実運用で最もイライラするのは **ホスト側がスリープ / クラッシュしたときに点きっぱなしになる** ケース。

ハード機構は不要。ファーム側に

> N ミリ秒ハートビートが来なければ自動消灯

を入れるだけで解決する。数十行の話なので入れる価値が高い。現行製品の弱点でもある。

### その他

- スリープ復帰後の USB 再列挙時の振る舞いを決めておく
- USB2 の 500mA 制約が明るさ設計に効いてくる

## 8. 戦略

### ソフト先行を推奨

1. まず既製の USB HID ライト（blink(1) 互換など）向けに、良い CLI + 常駐デーモンを OSS で出す
   - スケジューラ
   - webhook 受け口
   - プロセス終了時の自動消灯
   - CI 連携
2. ユーザーが付いてから、ハードを考える

差別化要素がソフトにしかない以上、在庫リスクと最悪のサポートコストを先に抱える理由がない。

### ソフト側の狙いどころ

- `blink1-tool` は既に OSS / OSHW で公開済み。**「CLI で光る」だけでは互換品扱いにしかならない**
- 今なら GUI ではなく、**デーモン + YAML/TOML 設定 + systemd / launchd 連携 + webhook 受け** のほうが刺さる層がいる
- 「日本で普通に買える」だけでも差別化になる

### 価格の現実

BOM は数百円でも、筐体・パッケージ・小ロット・サポートを載せると ¥2,000〜3,000 で売っても相当薄い。
Luxafor が ¥6,000 前後で成立しているのは法人経費で落ちるから。個人向け単体だとかなり厳しい戦いになる。
