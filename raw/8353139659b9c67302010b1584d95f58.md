# 共有Wikiにおける UserCSS 変更をめぐる摩擦の整理

Cosense の共同プロジェクト「井戸端」で 2026 年 6 月〜8 月に起きた、UserCSS デザイン変更をめぐる一連の議論とその後の対人摩擦について、公開ログをもとに外部視点で整理したもの。人名はイニシャル表記（N, C, Y, Ny, S, T, Z, V など）。

## 背景

井戸端では「小人さん活動」と呼ばれる文化があり、メンバーが事前合意なしにプロジェクト共通の UserCSS 等を変更し、事後の告知と差し戻しで調整する運用が慣習的に許容されてきた。N はこの文化の中で特に活発な貢献者であり、2026 年前半だけでダークテーマ導入、フォント変更、インライン引用記法、引用ブロック、出典アイコン、打ち消し線、インデント表示など、十数件の見た目に関わる変更を行っている。

## 経緯の要約

### 第 1 幕：インライン引用記法の変更（6 月）

N がインライン引用記法のデザインを斜体スタイルから下線スタイルへ変更。「勝手に置き換えても大丈夫か」「あれなら差し戻せばいい」と自覚した上での変更だった。メンバーからは line-height のバグ指摘（Ny）、font-weight が意図せず太く表示される問題（S, C）、アクセシビリティ観点からの下線支持（Ny）、下線＝強調のイメージによる違和感（Y, S）など多様なフィードバックが寄せられ、N はバグを認めて修正し、投票も設置した（自分の案に不利な側に投票するなど、独断で押し切る姿勢ではなかった）。

この過程で C の曖昧な提案（「既存の引用記法をインラインで使えるようにするみたいなシンプルなもの」）を N が「屁理屈混じりの皮肉」「不可能な要求」と誤読して攻撃的に応答する衝突が発生。後に N は「相手が文脈を共有している前提で拡大解釈した」「意図の確認を怠った」と詳細な自己分析を書き、謝罪した。C も「わかりにくい書き方をして申し訳ない」と応じ、この時点では自己修正が機能していた。

### 第 2 幕：出典アイコン UserCSS の変更（7 月〜8 月）

N が既存の出典アイコン CSS のパフォーマンス問題（過去に「日記ページが重い」という苦情ログあり）を理由に変更案を導入。C は「文字が途中で切れるのが嫌」と反対し、「変更する側に説明責任が生じる」と主張。N は「では元の CSS の導入者は導入時に説明したのか。先に入れた者勝ちになる」と反論し、この非対称性の指摘自体は T も「問題意識はわかる」と認めた。

しかし N の応答スタイルは悪化。Y に対して「しっかり詭弁ですね♡」「他力本願ですね♡」と返し、C の発言を一文ずつ引用して誤謬を注釈する形式で解体（C が直後に追記した撤回・軟化を考慮しないまま）。8/2 の日記では「理不尽な要求」「居丈高な態度で指図される」「相手をする価値がない」と記し、C の融和的なコメント（「取り組みに感謝している」「否定するのもまた小人さん活動の一つ」）に対しても 8/6 に「ダメだこりゃ」「無能」と応じた。C はここでも謝罪している。6 月に機能していた自己モニタリングが 8 月には見られなくなった、という経時変化が観察される。

## 論点の整理

### 論点 1：「勝手に変えたのだから批判されて当然」か

**当然である**、という点に争いはない。N 自身も批判を受けること自体は拒否しておらず、告知・投票・可逆性の維持といった手続きは踏んでいた。ただし「批判されて当然」と「個々の批判が妥当」は別問題であり、批判側にも検討の余地がある。

- C の「変更側に説明責任」論は、無説明で導入された既存 CSS を現状として保護する点で「先に席を取った者勝ち」の構造を持ち、N の反論には正当性があった。
- C が一時提示した「記法そのものの無効化」は過去ページを壊す破壊的変更であり、影響の重さで言えばスレッド中最大の提案だった（本人は後に「推奨ではない」と追記）。
- 出典アイコンの件は「エゴで変える開発者 vs 迷惑する利用者」ではなく、性能（実測可能な問題）と美観（見切れ）という正当な関心が衝突する利用者間の調整問題だった。

### 論点 2：事前報告すれば足りるか

足りない。井戸端は全員が全ページを読むわけではなく、**報告は同意ではない**。一件ごとの手続きが丁寧でも、変更の認知コストは読者側に発生する。

### 論点 3：変更の総量

議論の中で最も強い批判はこれだった。個々の変更の是非ではなく、**一人のメンバーによる変更レートが共有環境の認知容量を超えている**という問題。事後調整で回す文化は変更頻度が低いことを暗黙の前提としており、高頻度の貢献者が現れるとその前提が壊れる。ただしこの文化自体は N 固有のものではなく（他メンバー V も事後報告型の変更を行い、感謝されている）、N はその規範を最大限に使う外れ値と位置づけるのが正確。また変更リストには明確な不具合修正やダークテーマ無効化手段の整備（退出経路の提供）も含まれ、すべてが押し付けではない。

### 論点 4：対人衝突の原因

ログから読み取れる範囲での仮説：

1. 長い議論の文脈を相手も共有している前提で発言を読み、曖昧な発言に確認なしで敵対的な意図を補完する傾向（N 自身が 6 月に自己分析済み）
2. 一貫して指摘側に回ることが多かった C に対する「毎回ダメ出しする人」というパターン認識の蓄積
3. C 側の実際の曖昧さ・小さな誤読（N が否定した「評価のため」という枠組みで要約し返した等。C 自身も後に誤りと認めた）
4. 設計思想への強い自我関与と、6 月中旬からの継続的な消耗
5. 批判や異論を論理検査にかけ、誤謬名を付けて突き返す議論スタイルの一般化（特定個人への敵意にとどまらない）

技術的な論点では N はしばしば正しいか議論に値する主張をしていたが、議論スタイルが相手の軟化や言い直しを降参として扱うため、内容で勝てる場面でも対人関係を損ない、「変更を全て放棄してフォールバックさせることも辞さない」と自らの貢献ごと焼く方向に向かった。

### 論点 5：空気の文化とガバナンス

根本には**暗黙規範で回るコミュニティと、明示的な論理・対称性ですべてを処理しようとするメンバーのプロトコル不一致**がある。N の「基準を示せ」「非対称だ」「投票で決めよう」という要求は、いずれも空気の明文化要求である。高文脈な場ではこれは「空気が読めない」と映るが、明文化されていない規範は読める人にしか従えず、「空気を読め」は読めない人には解読不能な要求でもある。

実際、婉曲な提案・軽い指摘・「様子見」といった井戸端的なフィードバックは N に届かず、唯一機能したのは T による明示的な承認の形をした介入（「責任は十分果たしている、気にしすぎなくていい」）だった。

対応の選択肢は概ね三つ：

1. **距離を取り慣れる**（S が実践。8/7 に「あまり違和感無くなってきた」）
2. **明示的に伝える**。皮肉や婉曲ではなく「内容ではなく頻度が負担」と、相手の言語である低文脈な形式で。空気の文化を守るために一人にだけ明文で話すという非対称な対応になる
3. **ガバナンス化**（変更頻度の上限、オプトイン原則、告知の集約など）。ただし明文ルールの導入自体が井戸端らしさを削る

最もコストが高いのは「空気で伝わることを期待し続けて伝わらず、日記で互いに不満を書く」現状のループであり、6〜8 月のログはそれが双方を消耗させる過程の記録になっている。

## 結び

居心地の悪さの原因を特定個人に帰すのは、感覚として自然でも構造的には不正確である可能性が高い。問題の核は、暗黙規範と明示規範の衝突が未解決のまま放置されていることであり、これは当人が去っても、次に熱量の高い貢献者が現れたときに再発しうる。同時に、手続きの丁寧さは応答の攻撃性を免罪しないし、貢献の量は認知コストの外部化を正当化しない。どの陣営も一枚岩で正しくはなく、論点ごとに切り分けて評価するのが、このケースへの最も誠実な読み方だと考える。
