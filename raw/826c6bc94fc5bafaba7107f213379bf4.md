# デライトとは何か：データ構造と他ツールとの比較から考える

> 2026年10月1日時点で、公開されているページ（開発者 宇田川（希哲）浩行氏のアカウント `KNo.F85E`、公式の使い方ページ、ユーザーによる解説輪郭）を外から観察してまとめたものです。内部の実装は公開されていないので、推測を含む部分はそう明記しています。

## 1. 概要

[デライト（Delite）](https://dlt.kitetu.com/)は、希哲社が開発・運営している知識管理サービスです。公式は「なんでもメモ」サービスと呼んでいます。

データ構造をひとことで言うと、次のようになります。

> **名前つきのノード1種類と、種類のない包含エッジ1種類だけでできた、全ユーザー共通の1つのグラフ**

ファイル、ページ、ノート、データベースといった「入れ物」はありません。すべての情報が同じ1つの空間に置かれ、画面はその空間の一部を切り取った「見方」にすぎません。

## 2. スキーマ

### 2.1 輪郭（ノード）

情報の単位は「輪郭」の1種類だけです。数え方は「1輪、2輪」です。

```
Outline（輪郭）
  id          : 知番（knumber）  例) F85E/555F-1328
                 = アカウント番号（自我知番） / 輪郭番号
  owner       : 描出主（作成したアカウント）
  name        : 知名（タイトル。一意でなく、空でもよい）
  body        : 描写（本文。輪符やリンクの記法を含むテキスト）
  created_at  : 作成日時
  updated_at  : 更新日時
```

- **知名**は検索の対象になります。他の輪郭と重複してもよく、空でも構いません。
- **知番**は自動で振られるIDで、`K#F85E/555F-1328` や `KNo.F85E/555F-1328` の形で表示されます。
- **アカウントも輪郭**です。`KNo.F85E` はアカウントであり、そのユーザーの輪郭はすべて `KNo.F85E/...` の下にぶら下がります。`KNo.1` は公式アカウント、`KNo.0` は新規作成フォームで使われる空の輪郭です。
- 輪郭番号には4桁（`B79A`）と8桁（`555F-1328`）が混在しています。最近の輪郭は `555F-` で始まるものが多く、前半は時期やブロックの区分かもしれません（推測）。

### 2.2 引き入れ（エッジ）

輪郭同士の関係は、ある輪郭を別の輪郭の中に入れる「**引き入れ**」の1種類だけです。反対に、入れ子から外すことを「引き外し」と呼びます。

```
Edge（引き入れ） : 親の輪郭 ──contains──▶ 子の輪郭
  - 多対多（親も子も何個でも持てる）
  - エッジに種類（述語）はない
  - エッジに属性値はない
```

画面では、吹き出し（「吹き描き」と呼ばれます）の外側に親、内側に子が表示されます。URLでは、親の一覧が `?bg=<知番>`、子の一覧が `?fg=<知番>` で見られるようです。

### 2.3 輪符（本文の中の参照）

本文に `{知名 K#XXXX/A-XXXX}` という形の「輪符」を書くと、その輪郭へのリンクになります。表示する名前は文脈に合わせて変えられます。

- `{K#/知番}` のようにアカウント番号を省略すると、その本文の書き手のアカウント番号が補われます。
- 知番を省略すると、名前での検索ページへのリンクになります。
- `+{輪郭 K#/XXXX}` と書くと、他の輪郭の本文をその場に展開できます（描写埋め込み。トランスクルージョンに当たります）。
- 外部へのリンクは `[名前 https://...]`、画像の埋め込みは `+https://...` と書きます。

**本文で参照したときにバックリンクができるかは、未確認です。** ユーザーの解説では「本文に貼るとリンクになる」「引き入れ欄に入れると引き入れになる」が別々の操作として書かれており、本文の参照は一方通行のリンクで、関係として記録されるのは引き入れだけである可能性が高いと考えられます。

## 3. 構造：入れ物のない1つのグラフ

### 3.1 空間は1つだけ

多くのツールには「入れ物」の単位があります。

| ツール | 入れ物 | 画面との関係 |
|---|---|---|
| マインドマップ（XMind など） | マップ＝ファイル | 画面＝入れ物。別のマップのノードとは基本的につながらない |
| Obsidian | Vault とファイル | 1ファイル＝1ノート |
| Notion | ページとデータベース | ページの木構造 |
| **デライト** | **なし** | **画面は、全体で1つのグラフの切り口** |

デライトでも、輪郭1つ1つはレコードです。開発者のアカウントには、おそらく約270万個の輪郭があります。なくなっているのはレコードではなく、レコードを包むファイルや文書という境界のほうです。

この空間はアカウントの間でも共有されています。輪符にアカウント番号が含まれているので、他の人の輪郭を参照したり引き入れたりできます。引き入れを「返信」として使うユーザーもいます。残っている境界は、書き直せるのは自分の輪郭だけ、という編集権限くらいです。

### 3.2 「文書」は見方として作られる

デライトで「1つのまとまった文書」に当たるのは、ある輪郭を中心に、その子と親を表示した画面です。これは入れ物ではなく見方なので、**同じ輪郭が何か所の「文書」にも同時に現れます**。

### 3.3 実例：開発者の日記

開発者のアカウントでは、日々の記録が次のように組み立てられています。

```
[希哲20年9月の睡眠] ─────────┐
[希哲20年9月30日の生活] ─────┤
[準第八期希哲黄金睡眠] ──────┼──▶ [希哲20年9月30日の睡眠]
[起床] [就床] [換気徹底] ─────┤        本文：「22時15分頃就床・入眠，翌4時55分…」
[熟睡感有り] [中途覚醒無し] … ┘        （語のほとんどが別の輪郭への輪符）
                                   ※親は合計21個
[希哲20年9月30日の生活] ──▶ 睡眠, 鯨読, 陶練, 入浴, 散歩, 家計 … （子は16個）
```

同じ「引き入れ」1種類で、次の2つを同時に表しています。

- **日付の階層**：年 → 月 → 日 → 生活 → 睡眠
- **概念による分類**：「熟睡感有り」「起床」などの概念輪郭が、それに当てはまる日の記録を束ねる。実質的にはタグと同じ働き

「体感6時間30分睡眠」「22時15分頃」のような値まで輪郭になっているため、輪郭の数は非常に多くなります。

### 3.4 階層ナビは「命名規則＋名前検索」で作られている

記録の上部に表示される「睡眠記録 ／ 希哲20年 ／ 9月 ／ 30日 ／ 日記 ／ 生活」や、前日・翌日へのリンクは、知番へのリンクではありません。名前による検索を使っています。

```
?kw=K#F85E & 希哲20年9月の睡眠&rdr
      │            │             └─ 完全一致した輪郭へそのまま移動
      │            └─ 命名規則「希哲{年}年{月}月{日}日の{分類}」で作った名前
      └─ このアカウント内に絞る
```

デライトの検索は、知名にほぼ完全一致する輪郭だけを返す設計です。そのため、**命名規則が実質的なアドレスとして機能**します。ただし、この規則はシステムが強制も検証もしないので、構造の正しさは使う人の規律にかかっています（「希哲20年」は希哲紀元の年号で、2026年に当たります）。

### 3.5 削除のかわりに「忘却」

削除機能はありません。不要な輪郭は自然に埋もれるに任せ、残したくないものは空欄で描き直して隠します。公式は、これを脳の忘却に近い仕組みだと説明しています。公開が前提なので、「消せないし隠さないからこそ、困るものは最初から書かない」という姿勢とも言えます。

## 4. 他の手段との比較

### 4.1 Workflowy（アウトライナー）

いちばん近い例えです。Workflowy もファイルがなく、全体が1本の巨大なアウトラインで、どの項目もズームすれば1枚のページになります。「空間は1つで、ページは見方」という点が共通しています。

| | Workflowy | デライト |
|---|---|---|
| 形 | 木（親は1つ。ミラーは後から加わった機能） | 網（親を何個でも持てるのが基本） |
| 並び順 | 手で決められ、それ自体が意味を持つ | 子の一覧は更新順に見える（並べ替えられるかは未確認） |
| 空間の範囲 | 基本的に自分専用 | 全ユーザーで共有、公開が前提 |
| 探し方 | 全文検索 | 名前の一致検索と、引き入れを辿ること |

> デライト ≒ Workflowy から「木構造」と「並び順」の縛りを外して網の目にし、全ユーザーの共有空間にしたもの

### 4.2 ZigZag（Ted Nelson）

ZigZag（zzstructure）は、ハイパーテキストという言葉を作った Ted Nelson が1990年代に考えた情報構造です。

- 単位は「セル」で、全体で1つの空間に置かれる（この点はデライトと同じ）
- セル同士は、名前の付いた「次元」に沿ってつながる。**関係に種類がある**
- ただし1つの次元の上では、前後の隣は1つずつしか持てない
- 画面では2〜3の次元を選んで、その断面を表示する

デライトとは、**単位が1種類で、木構造に縛られない**点が共通しています。一方、関係の持ち方は逆と言っていいほど違います。ZigZag は関係に種類がある代わりに数が制限されていて、デライトは関係の数に制限がない代わりに種類がありません。

### 4.3 マインドマップ

1枚のマップが閉じた入れ物です。100枚作れば100個の閉じた世界ができ、マップ同士はつながりません。デライトはその逆で、「マップ1枚」に当たるのはグラフの見方であり、同じ輪郭が何枚にも現れます。

### 4.4 Obsidian / Notion / Roam / Logseq / Tana

| ツール | デライトとの主な違い |
|---|---|
| Obsidian / Notion | フォルダやページの木構造が基本で、置き場所は1か所。全文検索が強いので、雑に書いても後から拾える |
| Roam / Logseq | ページとブロックが別の概念。双方向リンクが中心。Logseq はプロパティを持てる |
| Tana | スーパータグとフィールドで、型と属性値を扱える。デライトに欠けている部分を持っている |

リンクを名前ではなくIDで持つので、名前を変えてもリンクが切れない点は、ファイル名でリンクするツールより堅牢です。

### 4.5 ナレッジグラフ（RDF・プロパティグラフ）

| | RDF / プロパティグラフ | デライト |
|---|---|---|
| エッジの意味 | 述語やラベルで区別できる（`partOf`, `type` …） | 1種類だけ |
| 値 | リテラル値やプロパティとして持てる | 値も輪郭にするしかない |
| スキーマ | 定義して検証できる | 命名規則として使う人の頭の中にある |
| 問い合わせ | SPARQL / Cypher など | 名前のAND検索と、親子の一覧 |

## 5. 評価

### 5.1 強い点

- **何個でも親を持てる入れ子**：1つの分類に決めなくても整理できる。人の連想の仕方に近い
- **単位が1種類**：アカウントから一語まで、どんな粒度のものでも同じ操作でつなげられる
- **IDによる参照と表示名の自由**：名前を変えてもリンクが壊れず、同じ名前があっても衝突しない
- **入れ物がない**：同じ輪郭を複数の文脈に同時に置ける。ユーザー同士の参照も自然にできる
- **検索と作成が一体**：見つからなければそのまま書ける
- **書くときに経路を作れば、確実に辿れる**：命名規則と引き入れを守れば、何年分の記録も日付や概念から引ける

### 5.2 弱い点

- **エッジに意味がない**：「部分と全体」「分類」「属性」「言及」がすべて同じ引き入れになる。意味は名前と人間の解釈に頼るしかなく、機械的に推論できない
- **値を持てない**：「体感6時間30分睡眠」は数値ではなく輪郭なので、集計や範囲の指定ができない。値の種類だけ輪郭が増える
- **構造が命名規則に依存する**：表記が1文字ずれると名前で辿る経路が切れる
- **問い合わせが弱い**：本文の全文検索や、2段以上の関係を辿る検索は確認できなかった
- **曖昧な記憶からは探せない**：経路を作らずに書いたものは埋もれる
- **並び順で意味を表しにくい**（未確認）

### 5.3 限界

- 構造の品質は**使う人の規律で決まる**。システムは命名規則を強制も検証もしない（IDでのリンクは残るので、描き直せば直せる）
- 取り出せるかどうかは、**書くときに経路を作ったかどうかで決まる**。全文検索のあるツールとは発想が逆
- **公開が前提**なので、私的な情報や仕事の情報は置けない
- 作者本人の運用に大きく依存した設計で、他の人が同じ使い方を再現するのは簡単ではない
- 個人開発のサービスなので、データの持ち出し手段は使う前に確認したほうがよい（公開ページからは確認できなかった）

## 6. どう使うか

普段のメモの受け皿として第一級のツールにするより、長所が活きる用途に絞るのが現実的です。

| 向いている | 向いていない |
|---|---|
| 概念の辞書づくり（1語1輪郭で網を育てる） | 数値を追う記録（睡眠時間、家計の集計） |
| 形の決まった質的な記録（読書記録、振り返り） | 私的なメモ、仕事の情報 |
| 公開を前提に考えを育てる場 | 雑に書いて後から全文検索で探すメモ |

記録を続けるときのコツは次のとおりです。

- 命名規則は1〜2個に絞る（例：`{年}年{月}月の読書`）
- 引き入れ先は「日付の親」と「分類の親」に決め打ちする
- 前の回の輪郭を複製して書き換え、表記ゆれを防ぐ
- 後から逆向きにも辿りたい関係は**引き入れ**で、文章の中で触れるだけの参照は**輪符**で張る
- 完璧を目指さず、崩れたら描き直して直す

## 7. まとめ

デライトは、**入れ物のない1つの共有グラフに、単位1種類と関係1種類だけで、何でも描き込んでいく**ツールです。

ネットワークの形は自由に作れますが、関係の意味・値・スキーマは、システムではなく名前と本文と使う人の規律が担います。そのため、連想のネットワークや概念の網としては強く、構造化データのナレッジグラフとしては弱い、という評価になります。Workflowy の「1つの空間とズーム」、ZigZag の「単位の統一と木構造からの脱却」を受け継ぎながら、関係の型は持たないという立ち位置です。
