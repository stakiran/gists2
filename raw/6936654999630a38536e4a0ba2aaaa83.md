# q 生成AIの主軸はLong-Horizon Tasks能力なのだろうか。Long-Horizon Tasks、俺個人はほとんど使わないんだけどなぁ（単に解析するデータ量が多い等は除く）、実際そんなに使われてるのか？

# a
「開発・投資の主軸」としてはその通りで、「実際の利用の主軸」としてはまだそうでもない、というのが現状に近いと思います。

**なぜ主軸扱いされているか**

早期の2026年は、長期タスクエージェントが本当の閾値を越えたという自信ある主張で溢れており、METRは狭いベンチマークのスコアではなく、エージェントが失敗するまでにどれだけ長く有用な実行を維持できるかでAI進歩を追跡し始めたほか、Sequoiaは2026年を長期タスクエージェントの年と予測しています。単発の回答品質はモデル間で差がつきにくくなった一方、「仕事を丸ごと任せられる時間の長さ」は数字で伸びが見えて、かつ経済価値（人の作業時間の代替）に直結するので、ラボも投資家もそこを指標にしている、という構図です。

**実際どれだけ使われているか**

利用データを見ると、あなたの実感はかなり正確です。Anthropic自身のデータでは、個人利用（スポーツのスコア、製品比較、家のメンテなど）はClaude.aiの会話の35%から42%に増えており、対話しながら進める「augmentation」が52%、丸投げの「automation」が45%と、チャット的な使い方が依然として半分以上です。開発者側でも、Stack Overflowの調査ではAI全体の採用率が84%なのに対しエージェントの採用は31%で、しかも好感度は目立って低下しています。

**どこで使われているか**

長期タスクが実際に回っているのはほぼコーディング領域です。コーディングは消費者向けインターフェースからAPIへ移行しており、これは主にClaude Code経由で、作業を細かいエージェント的な呼び出しに分割しているとされます。ただし現場の評価は冷静で、今日の実用的価値は自律的なソフトウェアチームからではなく、強い仕様・強いハーネス・安価な検証・明示的なコンテキスト・積極的な操縦を伴う「監督されたソフトウェア運用」から来ている、今日の「長期タスクエージェント」の多くは、まだ失敗していないだけの脆いループだという声もあります。コーディング以外への展開については、企業はClaude Codeを非コーディング業務に使うという概念にまだ慣れていない段階とも指摘されています。

要するに、長期タスク能力は「ベンダーが競っている軸」であり「コーディングでは実用化が始まった領域」ではあるものの、一般的な使い方の主流はまだ短い対話や解析で、それを使わない人が多数派です。個人で必要性を感じないのは、むしろ普通だと思います。

# q MATANAやGAFAMのエンジニアもそうなの？

# a 
そこは事情が違って、大手テックのエンジニアは「例外」に近い側です。ただし数字の読み方には注意が要ります。

**数字だけ見るとかなり使われている**

Sundar Pichaiが2026年4月のGoogle Cloud Nextで公表した数字では、新規コードのAI生成率は2024年10月の約25%、2025年秋の50%から、2026年4月には75%に達しています。Metaでは、Claudeベースの社内コーディングエージェントDevMateがすでに全コード変更のおよそ半分を提出しているとされ、Anthropic自身については、社内コードの大部分がClaude Codeで書かれていると公表資料で述べられています。Stripeの社内エージェントMinionsは週1,300件以上のPRをマージしており、IssueからPRまで人が途中介入せず一気通貫で実行する設計です。

**ただし「Long-Horizon」の中身は限定的**

「AI生成」は「AIが提案し人間が承認・編集したコード」の意味で、すべてのコミットは人間のレビューと自動テストを通っており、AIが単独でデプロイしているわけではありません。つまり実際に回っているのは「Issueを渡すと計画・実装・テスト・PR作成までやる」という数十分〜数時間規模の粒度で、これに「一人のエンジニアが複数のエージェントを並列に走らせ、要所で承認だけする」という形が乗っている、というのが現状の姿です。数日〜数週間の完全自律という意味でのLong-Horizonは、大手でもまだ主流ではありません。

**もう一つの注意点は「数字が半ば目標値」なこと**

MetaのCreation Orgでは「65%のエンジニアがコードの75%以上をAI経由で書く」という目標が設定されており、実質的に現場ではノルマとして機能しているという指摘があり、AI使用量を最適化すると、役に立たない場面でも目標達成のためにAIを通すという指標の歪みが起こります。「使われている」と「使うよう指示されている」の区別がつきにくい状態です。

**個人利用と違う理由**

彼らが使えているのは個人の努力ではなく、コードレビューをAI執筆前提で設計し直したり、エージェント向けに仕様書の書き方を変えたりといった、組織としての投資があるからです。エージェントは検証（テスト、CI、レビュー）が安く整っている環境でしか価値が出ないので、それが揃っている大手のコーディング業務で先に普及し、個人の解析用途や非コーディング業務では実感がない、という構図は自然だと思います。
