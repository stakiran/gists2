# kairon の agents.md に足すと面白そうなエージェント案

# =====

# weather-headsup
condition: 現在の時が 6～9 のとき、かつ今日まだ自分のログに記録がないとき

〈自分の街〉の今日の天気を WebSearch で調べ、雨・強風・猛暑など「傘や服装の判断に関わる情報」がある場合のみ、`inbox.md` の末尾に 1 行追記してください。

- 形式: `YYYY-MM-DD HH:MM | ☔ 午後から雨。傘を。` のような一言
- 特筆すべき天気でなければ inbox には書かず、ログにのみ「平穏につきスキップ」と記録
- 追記は Read → 全文組み立て → Write の手順で行い、既存内容を壊さないこと

# journal-nudge
condition: 現在の時が 21～23 のとき、かつ今日まだ自分のログに記録がなく、かつ `journal/` 配下に今日の日付のファイルが存在しないとき

`inbox.md` に「今日の日記がまだです。一言だけでも」と 1 行追記してください。書き方は weather-headsup と同じ手順で。

- Glob で `journal/*.md` を確認し、今日の日付（YYYY-MM-DD）を含むファイルの有無で判断すること
- すでに日記があればログに「日記あり、静観」とだけ記録

# downloads-watcher
condition: 毎回（ただし前回実行から 2 時間以上空いているとき）

`watch/` ディレクトリの疑似ファイル監視を行ってください。

1. Glob で `watch/` 配下のファイル一覧を取得する
2. 自分のログの最終行に前回のファイル一覧が記録されているので、それと比較する（ログがなければ初回とみなし、現在の一覧を記録して終了）
3. 新規ファイルがあれば、その名前を `inbox.md` に「📥 新着: <ファイル名>」として追記する
4. 最後に、現在のファイル一覧をログの新しい行として記録する（形式: `YYYY-MM-DD HH:MM | files: a.pdf, b.txt`）

# news-scout
condition: 平日の朝（6～10 時）に 1 回くらい。土日は動かない

自分が関心のあるトピック（例: AI エージェント、知的生産、ローカル LLM）から今日はどれか 1 つを選び、WebSearch で直近のニュースを調べ、最も面白い 1 件を 2～3 文で要約して `inbox.md` に追記してください。

- 選んだトピックと要約した記事の URL をログにも残すこと
- 直近 3 回のログを見て、同じトピック・同じ記事が続かないようにすること

# pipeline-summarizer
condition: `logs/news-scout.log` に今日の記録があり、かつ自分のログに今日の記録がないとき

news-scout が今日収集した内容（ログと inbox.md の該当行）を読み、「今日の一言インサイト」に圧縮して `daily-insight.md` の末尾に追記してください。他エージェントのログを発火条件に使う、パイプラインの例です。

# log-gardener
condition: 日曜、かつ自分のログに今週の記録がないとき

`logs/` 配下の各ログを Glob と Read で点検し、100 行を超えているものがあれば次を行ってください。

1. 古い行（先頭側）を 3～5 行の要約に圧縮する
2. 「== YYYY-MM-DD までの要約 ==」という見出し行に続けて要約を置き、直近 20 行はそのまま残す
3. どのログを整理したかを自分のログに記録する

kairon 自身の記憶（ログ）を手入れする、メタエージェントの例です。

# weekly-review
condition: 日曜の夜（18 時以降）、かつ今週まだ動いていないとき

`logs/` 配下の全ログを読み、今週 kairon が「何を・何回・なぜ」やったかを 10 行以内の週報にまとめ、`reviews/YYYY-Wnn.md` として Write してください。スキップ判断（動かなかった理由）も 1～2 件拾うと振り返りとして面白くなります。

# idea-sparker
condition: 自分のログを見て、前回の発火から 3 日以上空いているとき。時間帯は問わない

ランダムに選んだ 1 文字から連想する名詞を 5 個挙げ、そのうち 1 つと「自分の最近の関心事」を強制的に掛け合わせたアイデアを 1 個だけ `inbox.md` に追記してください。形式: `💡 <アイデア一言> （<名詞> × <関心事>）`。「3 日にいっぺんくらい不意打ちで来る」曖昧なルーチンの例です。

# =====

# 補足
狙いを補足すると、weather-headsup / news-scout は外界を条件と入力に使う例（WebSearch があるので API 連携ゼロで書ける）、journal-nudge はファイルの状態を条件にする例、downloads-watcher はログを状態ストアに使って疑似ファイル監視を実現する例です。pipeline-summarizer は他エージェントのログを発火条件にする「ログ経由のワークフロー編成」、log-gardener / weekly-review は kairon が自分自身の記憶を手入れ・振り返りするメタ層、idea-sparker は「3日にいっぺんくらい」という cron に書けない曖昧ルーチンの実演です。

設計上ひとつ提案を仕込んであります。エージェントの出力先を inbox.md に一本化する運用です。権限が Write までしかない以上「通知」はできないので、人間が1日1回見る受信箱を用意して全エージェントがそこに書く、という規約にすると出力が散らばりません。あとは condition 内の「自分のログ」参照が現行プロンプトの logs/<名前>.log 規約とそのまま噛み合うので、このファイルの中身を agents.md に貼れば動くはずです。

まずは weather-headsup と idea-sparker あたりの2体だけ足して心拍を回し、judgement の精度（スキップ判断が意図通りか）をログで確認してから増やすのがおすすめです。
