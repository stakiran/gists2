# q 「Microsoft Decision-1(判定特化・入力$0.042/100万トークン・出力無料)のような「小さく速い判定モデル」でルーティングや継続/停止を判断する設計が標準になりつつあります。大型モデルに全部任せる構成のコストを見直す材料です」 jev も同系統？

# a

はい、同じ系統です。Jev(TypeSafe社)は、文章を生成せず「判定」だけを返すモデルの代表例で、Decision-1はその後を追う形で出てきました。

**共通点**

- **使い方が同じ:** 入力と、あらかじめ決めた選択肢を渡すと、1回の処理で各選択肢の確率を返します。形式もYes/No、多肢選択、段階評価の3種類で同じです。
- **用途が同じ:** LLMに回答を採点させる処理(LLM-as-a-judge)、問い合わせの振り分け、RAGで取ってきた文書が関係あるかの判定、エージェントの制御などです。
- **料金が同じ:** どちらも入力100万トークンあたり0.042ドルで、出力は無料です。偶然とは考えにくく、Microsoftが価格をJevに合わせてきたように見えます。

**違い**

| | Jev(TypeSafe) | Decision-1(Microsoft) |
|---|---|---|
| 公開時期 | 2026年9月15日ごろ | 2026年10月9日 |
| ベースのモデル | 公表されていない | Qwen3.5-9B |
| 提供先 | Braintrust、OpenRouter、TypeSafeの順番待ちリスト | Microsoft Foundry、OpenRouter |
| 速さ | 1回あたり0.07〜0.5秒(TypeSafe公表) | GPT-6 Solの約35倍速い(Microsoft公表) |
| 強み | このジャンルを作った先駆者で、第三者による検証例が出始めている | Azure・Foundryとの統合。今後MAIやOpenAIのモデルをベースにした版も出す予定 |

**to Bとしての見方**

このジャンルは、9月にスタートアップが切り開き、1か月足らずでMicrosoftが同じ価格で参入しました。カテゴリとして定着しそうです。

導入するときの注意点は、どちらにも共通します。

- **理由が返ってこない:** 判定結果の根拠が出ないので、問題が起きたときに原因を追いにくくなります。
- **間違いは起こる:** 返す形式は常に正しくても、中身が間違うことはあります。計算、数を数えること、日付の前後関係は苦手です。
- **悪意ある入力に弱い:** 入力に仕込まれた指示(プロンプトインジェクション)で判定が変わることがあります。
- **公表数値はベンダー発表:** 速さや精度の数字は各社の自己申告です。本番で自動判定させる前に、自社のデータで確率の信頼度と判定の境界値を検証する必要があります。

なお、日報の時点ではJevとの関係を書いていませんでした。次回から、こうした競合や先行例があれば併記するようにします。
