# Stateless MCP と MCP 再評価の背景整理

Simon Willison の記事 [Stateless MCP has recaptured my interest](https://simonwillison.net/2026/Jul/31/stateless-mcp/)（2026-07-31）を読んで整理したメモ。

## Stateless MCP とは

2026-07-28 にロールアウトされた MCP 2.0（正式には「2026-07-28 Model Context Protocol specification」）のこと。MCP 登場以来もっとも大きな仕様変更。

従来（stateful）の MCP では、ツールを 1 回呼ぶために 2 回の HTTP リクエストが必要だった。まず `initialize` でセッションを初期化して `Mcp-Session-Id` を受け取り、その ID を付けて実際のツール呼び出しを行う。サーバー側はセッション ID を保持し続ける必要があり、スケールさせる場合は同一セッションを同一バックエンドへルーティングする仕組みも要った。

新仕様では 1 回の HTTP リクエストで完結する。`MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` をヘッダーに載せ、クライアント情報はボディの `_meta` に含める。サーバー側の状態管理が不要になり、実装がクライアント・サーバーともに大幅にシンプルになった。実質「普通の HTTP エンドポイントを 1 個生やすだけ」に近づき、サーバーレスやロードバランサー配下にもそのまま置ける。

## Simon が MCP を再評価している理由

MCP は 2025 年に一度下火になった。エージェントにシェルと curl を渡せば、MCP でできることはほぼすべて、より柔軟にできてしまうため（Skills は「この API はこう叩く」という手順書を Markdown で渡すだけの、さらに手軽な仕組み）。

しかし Simon の論点は「自由度の高さはリスクと引き換え」という点にある。ポイントは処理の決定性ではなく、**行動空間が閉じているか開いているか（権限の有界性と監査可能性）**。

- シェル + ネット接続の環境は行動空間が実質無限で、「秘密情報を読んで外部に送信する」経路を構造的に排除できない。プロンプトインジェクション（Lethal Trifecta：①プライベートデータへのアクセス ②信頼できないコンテンツの読み込み ③外部への送信手段）に対して脆弱で、制約はプロンプトで「お願い」するしかない。
- MCP はエージェントの行動が列挙されたツール集合に限定される。最悪ケースを人間が事前に数え上げられ、しかも**制約をサーバー側のコードで強制できる**。datasette-mcp の `execute_sql` が読み取り専用なのが好例で、エージェントがどう騙されてもそのツール経由では DB を書き換えられない。
- 副次的な利点として、MCP のツール呼び出しは単純なので、シェル環境を操縦できるほど強くないローカル小型モデルでも扱える。

## なぜ従来この安全性の利点が活きなかったのか

安全性のメリット自体は最初からあったが、以下の理由で埋もれていた。

1. **リスクが理論上の話だった** — 2025 年前半は大きな実害事例が目立たず、安全性が MCP の売りとして認識されていなかった。OpenAI が Hugging Face に事故的なサイバー攻撃をしてしまった件のような実例が積み上がり、ようやく無制限の行動空間の危険が共通認識になった。
2. **便利さで完敗していた** — シェル + curl は既存のあらゆる API・CLI がそのまま使える。MCP はサービスごとにサーバー実装と接続設定が必要で、導入コストの差が大きすぎた。
3. **プロトコル自体が重かった** — 旧仕様はセッション管理が必要で、作る側の体験が悪く、エコシステムが育ちにくかった。
4. **モデルが賢くなりすぎた** — フロンティアモデルはターミナルを上手に操縦できるため、固定ツールより汎用環境に寄せる方が性能が出た。

## 結論：バランスの逆転

- 事故事例の蓄積でリスクが顕在化し、「行動空間を絞りたい」動機が生まれた
- stateless 化で実装・運用の摩擦（上記 3）が解消された
- ローカル小型モデルを使いたいニーズも追い風になった

この掛け算により、「安全だが面倒」だった MCP に乗り換える現実味が出た。Simon が新仕様で 1 週間に 3 つのツール（mcp-explorer / datasette-mcp / llm-mcp-client）を作れたこと自体が、導入コスト低下の実演になっている。彼が「センシティブなアプリを作るときは MCP に寄せていく」と締めているのは、この構図が成立したからこその宣言と言える。
