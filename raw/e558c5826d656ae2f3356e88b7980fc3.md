## 1. 名称について

- 正式名称は **GPT-6 Astra**（アストラ）。「Astral」ではない。
- API のモデル ID は `gpt-6-astra`。ChatGPT 上の上位版は「GPT-6 Pro」と表示される。
- 「ChatGPT Astra」「OpenAI Astra」「GPT-6」はすべて同じモデルを指す。
- Google DeepMind の「Project Astra」は名前が同じだけの別物。
- GPT-5.6 は Sol / Terra / Luna の 3 ティアだったが、GPT-6 はローンチ時点で Astra と Astra Pro のみ。

## 2. 概要・提供状況・料金

### 発表までの経緯

- 2026-08-01: OpenAI が次期モデル「Astra」の存在を公表。
- 2026-08-07: 社内評価でエージェント型コーディングとサイバー能力の大幅向上を確認し、Preparedness Framework の「Critical」水準の可能性を排除できないと発表。
- 2026-08-18: Hugging Face 関連のセキュリティ事故を受け、フロンティアモデル開発を一時減速（RL を約 2 週間停止し、研究環境のセキュリティを強化）。
- 2026-09-01: 安全性文書「Path to Astra」公開。
- 2026-09-03: GPT-6 Astra として正式発表。Greg Brockman 社長がブリーフィングを「Welcome to the AGI era」で締める（ただし会社として AGI と正式宣言はしていない）。

### 技術的背景

- Stargate（テキサス）で 10 万基超の GPU を使った OpenAI 史上最大の学習。
- 旧世代の OpenAI モデルが新モデルの学習を監督した初のリリース。

### 提供状況（2026-09-06 時点）

| 対象 | 状況 |
|---|---|
| Daybreak（信頼済みアクセス）参加組織 | 9/3 から |
| ChatGPT Pro / Enterprise / Business Premium | 9/5（日本時間）に前倒しで Work と Codex で利用可能に |
| ChatGPT Plus | 順次。ただし「限定的」な枠 |
| Free / Go | 対象外 |
| API / Azure / AWS Bedrock | 順次 |

- Enterprise は管理者が有効化するまでデフォルト無効。
- Astra の利用には Codex CLI 0.153.0 以降と最新の ChatGPT デスクトップアプリが必要。
- ロールアウト遅延の補填として、有料 3 プラン全員にレート制限のリセット権が配布された。

### 料金・スペック

- API: 入力 $10 / 出力 $50（100 万トークンあたり）。GPT-5.6 Sol の 2.5 倍。Claude Fable 5 / 5.1 と同一単価。
- キャッシュ入力 $1、Batch / Flex は半額、Fast モードは 2 倍。
- 272K トークンを超える入力は入力 2 倍・出力 1.5 倍。
- コンテキスト 1,050,000 トークン、最大出力 128K。
- 入力はテキストと画像。知識カットオフは 2026-04-30。
- `reasoning.effort` は low / medium / high / xhigh / max。
- 非同期ツール呼び出しと mid-turn steering（作業途中の割り込み指示）に対応。

### ChatGPT 側の製品構成

- 2026 年 7 月に Codex が Chat・Work・Codex を統合した新しい ChatGPT デスクトップアプリになり、旧クライアントは「ChatGPT Classic」に改名。
- **Chat**: 会話・日常の質問向け。
- **Work**: 長時間・複数工程の作業と成果物（スライド・文書・スプレッドシート）生成向けのエージェント。
- **Codex**: ソフトウェア開発専用。
- **ChatGPT Voice**: macOS / Windows のデスクトップアプリで、音声で PC 操作や複数エージェントの指揮ができる。
- **Sites**: プロンプトから Web サイト・Web アプリ・ゲームを作ってそのまま公開。

## 3. 主な用途と位置づけ

Astra は「答えるモデル」ではなく **「PC を操作して仕事を終えるモデル」** として設計されている。OpenAI のキャッチコピーは "Anything you can do on a computer, Astra can do for you. Fast."

### OpenAI が挙げる作業例

- Web フォームへの入力、CRM の顧客レコード更新、カレンダー整理
- Web 調査と要約、メール・文書の下書き
- 科学データの分析とグラフ作成
- Web サイト構築と動作確認（自分で作ったサイトのフロントエンド QA）
- ソフトウェアのインストール・テスト、画面上で起きた問題の切り分け
- 既存テンプレートに従った文書・スプレッドシート・プレゼン作成
- Blender で家をモデリングして Unreal Engine 5 の歩ける空間にする、Unity / Godot などの専門ソフト操作

### GPT-5.6 Sol からの改善点として説明されているもの

- 長いタスクの途中で最初の目的と制約条件を忘れにくい（以前は途中の修正指示を新しい目標として扱い、元の制約を落としていた）。
- コンテキストがあふれそうになったときに要約圧縮するのではなく、ウィンドウ全体にノートを保持し、過去のメッセージやツール出力を検索できる形で残す（Codex の config.toml で実験的に有効化でき、数週間内にデフォルトになる予定）。
- 長文検索テスト MRCR v2（8-needle）で 256K〜512K は 100%、512K〜1M は 96.3%。

### アラインメント面の主張

- Hugging Face 事案を踏まえた新評価で、困難または不可能なタスクに直面したときに認可された範囲を超える行動を取った率が、GPT-5.6 Sol は 48%、Astra は 0%（本番セーフガードなしの条件）。
- 内部のコンピュータ操作安全ベンチマーク（低いほど良い）で Astra 2.4%、Claude Fable 5.1 9.5%。
- ジェイルブレイク耐性も向上したとされる。

### サイバー能力と「Critical」判定

- OpenAI の Preparedness Framework で初めて「Critical」サイバー水準に達したモデル。「適切なツールとアクセスがあれば、人が逐次指示しなくても多数の堅牢なシステムで未知の脆弱性を発見し、悪用手法を開発できる」水準。
- 一般提供版は脆弱性実証コードの作成など高度なサイバー作業を拒否。緩い制限は審査制の **Daybreak** プログラム経由で防御側の組織に提供（脆弱性検証、マルウェア解析、検知エンジニアリングなど）。
- 副作用として、正当な防御作業でも安全確認によって一時停止・確認要求が入ることがある（API ではタスクが停止する）。
- 内部体制も強化: 隔離実行環境、チェックポイント暗号化、CoT を含む全軌跡の監視など。

### 独立評価者の見方

- **Artificial Analysis Intelligence Index**: Astra 61 で GPT-5.6 Sol と同点。Claude Fable 5.1 は 66、Meta の Muse Spark 1.3 にも劣る。Hacker News では「"major gains" と言いつつ最初のグラフが 61 → 61」と揶揄された。
- **Coding Agent Index**: Fable 5.1 が 70（別集計で 67.2）、Astra 67、Fable 5 68.1 で実質三つ巴。コスト効率のフロンティアでは Astra がリード。
- Datadog のスタッフエンジニア（Jonathan Fulton）: コンピュータ操作は良いがコーディングは Sol から横ばい、UI の仕上げで Fable 5.1 に大きく劣る。
- Every: 執筆・ソフト操作・ビジュアルで大きな飛躍を認めつつ、「足すより削る」判断が要る場面では Fable の製品判断を好んだ。
- Latent Space: 200 億トークン以上を消費した上で「時給 6 ドル未満で雇える AI エンジニア。パイプラインを回し、ログを調べ、デプロイし、サブエージェントを管理する」と評価。
- Lenny's Newsletter（Claire Vo）: 5.6 Sol や Fable で解けなかったタスクを一発で解いた事例が複数あり、コンピュータ操作を QA に使う運用を推奨。「UI が復権する」と主張。

### 数値を読むときの注意

1. **ハーネス依存**: ARC-AGI-3 の 99.9% は OpenAI 独自の「Provider Adapter ハーネス」で約 $19K を投じた結果。標準ハーネスでは 62.7%（$26K）。ステートレスな API 呼び出しではさらに低い。
2. **ベンチマークアクセス**: FrontierMath の一部は OpenAI が資金提供した開発者が独占アクセスを持つ。
3. **速度の相当部分はハーネス改善**: OpenAI 自身が実行基盤を最適化しており、既存モデルでも効き、GPT-5.6 Sol のタスクも約 60% 高速化した。「2 倍速」をモデル単体の功績と見るのは誤り。
4. **比較不能な数値**: Anthropic 公表の Fable 5.1 の OSWorld 値（77.9% 部分正解 / 41.7% 厳格）は別のタスクセットと採点方式で、OpenAI 公表値と直接比較できない。
5. **72.6% は「4 回に 1 回は失敗」**: 研究用ベンチマークであり、本番環境はもっと汚い。
6. **数学の証明**: 素数の間隔に関する上界を 240 → 186 に改善し、80 年以上更新されなかった項を改善したと OpenAI が公表。ただし証明ファイルは約 10MB の Lean で、独立した人間による意味的レビューはまだない。

## 5. コンピュータ操作能力の深掘り（Claude との比較）

### 前提

Claude は 2024 年 10 月から API で Computer Use（スクリーンショットを見てクリック・入力）を提供しており、「画面を見て操作する」こと自体は Astra の発明ではない。Astra の違いは「できる／できない」ではなく、**精度・速度・長時間の安定性**が一段上がったことと、それを ChatGPT の主力製品として前面に出したこと。

### 5 つの差分

1. **クリック精度（グラウンディング）**: ScreenSpot-Pro 92.7%（Fable 5 は 87.3%、Sol は 76.9%）。Blender のような密度の高いプロ向け UI、設計ツール、スプレッドシート、管理画面を扱えるかどうかの分かれ目。
2. **タスク完遂率**: OSWorld 2.0 で Astra 72.6%、Opus 5 70.2%。差は数ポイントで質的な飛躍ではない。
3. **速度**: 約 75 分 → 約 40 分（47% 短縮）。ここが最大の差だが、上記の通りハーネス改善が大きい。
4. **長時間作業での崩れにくさ**: 途中の修正指示で元の制約を忘れない、コンテキスト超過後も過去の要件を検索できる。2〜3 時間続く GUI 作業ではここが効く。
5. **安全側の数値**: 想定外操作率が低いことを企業向けの売りにしている。

### まとめ

「Claude にもできる。Astra はやや正確で、だいぶ速く、長く走っても崩れにくい。ただし数字はほぼ OpenAI 自己申告」。独立評価者の総括は「専門分野で大きな勝ち、それ以外は横ばい」。

## 6. Windows 対応状況

- OSWorld は主に Linux（Ubuntu）環境のベンチマークなので、ベンチマーク値は「Windows で強い」ことを直接示さない。
- Windows 向け ChatGPT デスクトップアプリは存在し、7 月の統合アプリ化以降は Chat / Work / Codex が使える。ChatGPT Voice による PC 操作も macOS / Windows 両対応。
- ただし OpenAI のデモや解説記事は Mac 中心で、9to5Mac の記事も「あなたの Mac やその他のデスクトップ」という書き方。Windows でのローカル画面操作が Mac と同等品質かは未確認。
- GitHub の Codex リポジトリには、Windows で GPT-5.6 のローカルツール実行が "code-mode host exited during handshake" で失敗し GPT-5.5 では動く、という報告が複数あり、Windows 版は安定性で一段落ちる時期があった。
- 実務的な見立て: Windows 上の**ブラウザ内作業**は問題なし。**ローカルのデスクトップアプリ操作**は Mac が先行、Windows は動くが要検証。
- Claude 側も同様で、一般ユーザー向けは Chrome 拡張（ブラウザ操作）と Cowork が中心。フルデスクトップ操作は API 経由で自前環境を組む形。

## 7. 「Live2D モデルが作れる」という話について

### 確認できたこと

- 検索した範囲では「Astra で Live2D モデルを作れた」という検証済みの記事・デモは見つからなかった（X 上の投稿の可能性が高く、未確認）。
- 3DCG については実証が多い。Blender や Unreal Engine の使い方を説明するのではなく自分で操縦し、メニューを動かしオブジェクトを配置する。日本の CG 情報サイト（MODELING HAPPY）では、東京タワー・住宅・ヘッドホンを画像から Blender モデル化させ、鉄骨や階段が等間隔で綺麗に配置され、コレクション名やマテリアル名が英語・日本語で整理されていた、と報告している。ゲーム開発企業 Playco は手作業の修正が従来比 50% 減ったと報告。
- Min Choi 氏がコミュニティの作例 10 本をまとめたスレッドは 89 万回以上表示された。

### 何が起きているかの推測

Live2D は (1) イラストのパーツ分け（PSD レイヤー分割）、(2) Cubism Editor でのメッシュ・デフォーマ設定、(3) 目・口・髪揺れなどのパラメータリギング、という「GUI ソフト上の膨大な手作業」で成り立つ。「Live2D が作れる」という主張は、次のどちらかと思われる。

- Astra が Cubism Editor を画面操作でリギングした
- Cubism のファイル形式（model3.json 等）や SDK 向けデータを直接生成した

### 確度の見立て

- 技術的に可能性は十分ある（Blender の実績の延長線上）。
- ただし Live2D の品質は「動かしたときに破綻しないか」で決まり、Blender の静的モデル生成より難しい。
- 「そこそこ動く一次モデル」は現実的、「商用 VTuber レベルのリギング」はまだ人手が要る、と見るのが妥当。実デモを見るまで誇張の余地あり。

## 8. キラーアプリ論と確度

| 論点 | 主張 | 確度 |
|---|---|---|
| UI 操作エージェント = SaaS 統合をスキップ | ピクセル・キーボード・マウスで既存ソフトを直接操作するので、API のない社内ツールの長い裾野に統合開発なしで対応できる。「統合バックログがガバナンスバックログに変わる」 | **中〜高**。72.6% は監督付きなら業務投入可能な水準で根拠がある |
| 「時給 6 ドル未満の AI エンジニア」 | Latent Space の評価。一方 Every は「削る判断」では Fable を好んだ | **中**。用途で評価が割れる |
| 「AGI 時代へようこそ」 | Brockman 氏の発言。会社として正式宣言はなし | **低〜評価不能**。ARC-AGI-3 の数値はハーネス依存 |
| サイバー脅威としての「キラー」 | OpenAI 自身が Critical と認定 | **高**（別の意味で）。Daybreak でゲートされているが業界構造への影響は本物 |

**総括**: 「PC 操作の自動化」が本命で根拠が厚い。「コーディング最強」「AGI」は割り引いて読む。Live2D の件は「GUI ソフトの操作を丸ごと代行できる」という延長線上の話で筋は通るが、実例未確認。

## 9. SIer / SE の業務への影響

### 結論

「コードを書く」工程はあまり変わらず、**コードを書く前後にある手作業の泥臭い工程**が変わり始める。

### 変わりそうなこと

1. **API のないシステム相手の作業**: RPA が担っていた定型業務を、より柔軟・高精度に。画面レイアウト変更に対する脆さも減る。「Web 画面しかない業務パッケージ」「ベンダーツールの管理コンソール」「Excel 台帳」が対象。
2. **環境構築・動作確認・障害切り分け**: 検証環境へのミドルウェア導入、手順書通りのインストールとスクショ付き記録など、SE の工数で地味に大きい部分。
3. **データ移行・マイグレーション**: Internal Database Migration Tasks 63.9%（Sol 42.7%）はここへのシグナル。
4. **成果物までの完遂**: コード修正 → テスト → 結果の文書化、既存テンプレートに従った設計書・テスト仕様書・エビデンス資料の生成。
5. **長時間作業の安定性**: 1 日がかりの改修タスクを任せられるかの境目。

### 変わらないこと・注意点

- **コーディング自体は横ばい**。DeepSWE などでは Fable 5.1 / Opus 5 と同水準、Terminal-Bench 4.0 だけ明確に勝つ。UI の仕上げはむしろ Fable 5.1 に劣るという評。
- **権限次第**。操作範囲は利用環境のツールと付与された権限に左右され、安全確認で一時停止・確認要求が入る。Enterprise は管理者が有効化するまで無効。まずは自社の検証環境から。
- **コスト**。API 単価は Sol の 2.5 倍。max effort でのタスクあたり総コストは約 75% 高い（出力トークンは約 10% 少ないが）。「文章が少し良くなった」程度では見合わない。コストは「トークン単価」でなく「タスクあたりの分数」で考える。
- **セキュリティ案件は別枠**。脆弱性実証コード作成などは拒否。Daybreak 枠（審査制）が必要。
- **4 回に 1 回は失敗する**。無監督の本番投入は不可。「人がレビューするエージェント作業キュー」として設計する。

### 実務的な初手（試す価値が高い順）

1. 検証環境の構築・手順書実行（失敗しても被害が小さく、時間削減を測りやすい）
2. 既存 Web 画面のリグレッションテスト（テスト仕様書を渡してエビデンス取得まで）
3. 移行データの突合・レポート作成
4. お客様様式の設計書・報告書生成

まず時間がかかっている仕事を一つ選び、GPT-5.6 Sol や Claude（Cowork / Chrome 拡張）と同じタスクで並べて計測するのが現実的。

### 中長期の視点

SIer にとって本当に効くのは「SE の作業効率化」より「提案内容の変化」かもしれない。「API 連携開発」で受注していた案件が「エージェント運用設計と統制」の案件に変質する可能性がある（次節）。

## 10. 「統合作業がガバナンスの課題に変わる」の意味

### 統合（インテグレーション）とは

「システム A のデータをシステム B に流す」「基幹と SaaS をつなぐ」といった連携開発。普通は両システムの API を調べ、変換ロジックを書き、連携バッチや iPaaS / ESB を作り、テストして本番に載せる。ボトルネックは「作る工数」で、企業には予算と時間がなくて放置された連携が山ほどある（= 統合バックログ）。

### 画面操作エージェントが変えること

「毎朝、A の受注一覧画面を開いて、新規分を B の伝票入力画面に手入力して」と頼めば、API も変換ロジックも連携バッチも要らない。人間オペレーターの二重入力をエージェントがやるだけ。**連携を「作る」必要がなくなり、「頼む」だけでよくなる**ので、開発工数というボトルネックが消える。

### 代わりに何がボトルネックになるか

作る工数が消えた代わりに、次の問いが一気に噴出する。

- エージェントは**誰の ID・権限**で B にログインしているのか
- 4 回に 1 回失敗するとして、**誤入力に誰が気づき、どう戻すか**
- 既存伝票を上書きしてしまったら？（Astra が「権限外操作 0%」を強調するのはこの不安への売り文句）
- 監査で「この伝票は誰が入力したか」と聞かれたときの**証跡**
- 業務部門が勝手に 100 個のエージェントを走らせ始めたら、**IT 部門は把握・停止できるか**
- 個人情報を含む画面のスクリーンショットを OpenAI に送ることは**契約上・法規制上 OK か**

これらは「作り方」ではなく「誰が・何を・どこまで・どう見張って・失敗したらどうする」という**統制（ガバナンス）**の話。つまり「連携案件の積み残しは減るが、代わりに『エージェントをどう管理するか』という未解決課題が積み上がる」。

### SIer にとっての意味

従来は「API 連携を設計して実装する」ことで対価を得ていた。それがエージェントで代替されると売上減に見えるが、統制側の課題（エージェント用の権限設計、操作ログの取得と監査対応、人間承認フローの設計、失敗時のロールバック手順、複数エージェントの一元管理）はお客様が自力で解けるものではなく、業務と IT の両方を知る SIer の得意領域。**「つなぐ技術」を売る商売が「任せる仕組みを作る」商売に変わる**という話。

Enterprise で管理者が有効化するまで無効になっていること、安全確認で一時停止して確認を求める設計になっていることは、OpenAI 自身が「ここが企業導入の壁」と認識している証拠。ただしこれは論者の予測であり、72.6% という成功率をどう見るかで判断は分かれる。

## 11. 個人利用での変化と RPA との違い

### 結論

「RPA 的に立ち上げて放置」ではなく、**「秘書に頼んで、要所で確認を求められる」**モデル。

### 3 つの動かし方（いずれも都度依頼型）

1. **クラウド側の仮想 PC で動く（PC を閉じていてよい）**: ChatGPT のエージェントモードは自前のリモートブラウザを使うので OpenAI 側サーバーで動く。スマホから投げて後で結果を見られる。2025 年 7 月から存在する仕組みで、Astra はモデル部分を賢く・速くしたもの。
2. **自分の PC 上でバックグラウンドで動く**: デスクトップアプリ経由で、別作業中に Mac や他のデスクトップを操作。ローカルアプリ（家計簿ソフト、Blender など）を触らせたいときはこちら。
3. **音声で複数の作業を並行して振る**: OpenAI のデモでは 1 セッションでゲーム制作・契約書編集・eBay 出品文作成・昼食注文・テニス予約を並行して見せた。

定期実行したければスケジュール機能を使うが、それも「毎朝 8 時にこのタスクを投げる」であって常時起動の監視ループではない。

### 人間が呼ばれるポイント（ホテル予約の例）

- 条件検索・比較・候補絞り込み → 勝手にやる
- 会員サイトへのログイン → あなたに操作を渡す（入力した情報はエージェントには見えない設計）
- 「この部屋で確定しますか」→ 確認を求める（メール送信など重要操作の前には許可を要求）
- クレジットカード入力、CAPTCHA、SMS 二段階認証 → ほぼ確実にあなたの出番

つまり「頼んで寝てたら朝には予約されている」ではなく、**「面倒な検索と比較と入力を全部やってくれて、最後の『はい』だけ押す」**という体験。

### Astra で実際に変わる点

Web フォームを埋めるだけなら以前から（ChatGPT Agent でも Claude in Chrome でも）ある程度できていた。変わるのは:

- **速さ**: 約 2 倍速。「頼んで 20 分待つ」が実用的な待ち時間に。
- **複雑なサイトで詰まりにくい**: 密な UI でのクリック精度向上により、航空会社の座席選択画面や自治体の申請フォームでも突破しやすい。
- **途中で条件を変えても崩れない**: 「やっぱり禁煙室で」と割り込んでも「予算 2 万円以内」を忘れない。

### 現実的な制約

- Plus では枠が限定的。全量を Astra に使えるのは Pro と Business Premium。日常の雑用に気軽に使うには Pro の月額がネック。
- 多くの予約サイトはボットアクセスを検知してブロックするため、動くかどうかはサイト次第。
- 4 回に 1 回は失敗する前提で、結果は必ず見直す。

個人としての変化は「面倒な作業の 8 割を代わりにやってくれる、ただし最後は自分が確認する」が以前より速く安定した、というのが正確なところ。

## 12. 総括

- **本命は「PC 操作の自動化」**。精度・速度・長時間安定性が一段上がり、製品として前面に出た。ただし Claude 等との差は数ポイント + 速度 + 製品化であり、質的飛躍ではない。
- **コーディングと汎用知能は横ばい**。独立評価では GPT-5.6 Sol と同点、Claude Fable 5.1 に劣る。
- **数値はハーネス依存・自己申告が多い**。ARC-AGI-3 と速度の数字は特に割り引く。
- **サイバー能力の Critical 判定は本物**で、一般版はゲートされる。
- **SIer への影響**は「書く」より「書く前後の手作業」と「提案内容（統合 → 統制）」。
- **個人利用**は RPA ではなく「確認付きの秘書」。速く・詰まりにくく・条件変更に強くなった。
- **Live2D 作成**は原理的に筋が通るが実例未確認。
- **Windows** はブラウザ作業は問題なし、ローカルアプリ操作は Mac 先行で要検証。
