# GTD と ポストGTD の比較

生成AI（エージェント）に実行の大部分を任せられるようになったとき、「成し遂げる（Getting Things Done）」の中身はどう変わるかの整理。

## 前提の違い

| | GTD | ポストGTD |
|---|---|---|
| 想定している世界 | 自分の手で全部やる | 実行の多くをエージェントに委任できる |
| ボトルネック | 実行する手 と 覚えておく頭 | 何を頼むか決めること と 結果を信じてよいか判断すること |
| 根本の問題意識 | 未完了の事柄が頭に残って注意を奪う | 任せた結果を理解しないまま受け入れてしまう |
| 理想の状態 | 水のように澄んだ心（雑音がない） | 判断に必要なものだけが濃く残っている頭 |

## 単位と流れの違い

| | GTD | ポストGTD |
|---|---|---|
| 最小単位 | Next Action（自分の身体が次にやる一手） | 委任できる単位の仕事（望む結果・完了条件・やってほしくないこと） |
| 処理の形 | 逐次（ひとつ選んで、やって、次へ） | 並列（投げて、待って、検収する） |
| 中心になる作業 | 実行 | ディスパッチ と 検収 |
| 「見極め」の重み | 軽め（曖昧でも手を動かしながら調整できる） | 重い（最初に言語化しないと戻り時間が丸ごと無駄になる） |
| 「連絡待ち」リスト | 脇役 | 主役（相手が速くて多い） |
| 優先順位づけ | 全部書き出してから考える | 変わらない。むしろ逃げ場がなくなる |

## 「成し遂げた」の定義

| | GTD | ポストGTD |
|---|---|---|
| 完了とは | タスクが終わったこと | 自分がその結果に責任を持てる程度に理解していること |
| 終わっていないもの | リストに残っているもの | 自分が説明できないもの |
| 成果の総量を決めるもの | 自分の手の速さ | 自分が本当に分かっていることの量 |

## 残るもの・消えるもの・新しく増えるもの

**残る**
- 全体を見渡して、何に時間を使うか自分で決めること
- 「これは何か、望む結果は何か」と問うこと（むしろ重要度が上がる）
- 週次レビューの習慣（内容は変わる）

**消える、あるいは薄くなる**
- 分解と逐次実行の几帳面さ（エージェントがやる）
- 「忙しさ」による判断先送りの正当化（「できなかった」が言いにくくなり、「決めなかった」だけが残る）

**新しく増える**
- 検収：出力は「できました」と言うのが上手いので、中身を見て受け入れ可否を判断する仕事
- 委任の設計：どこを自分で握り、どこを任せるかを選び続けること
- 理解の維持：手を動かさなくなると検収の目が鈍るので、意図的に手を動かす時間を残す

## 一日の過ごし方（例）

| 時間帯 | GTD | ポストGTD |
|---|---|---|
| 朝 | 収集箱を見極め、リストに振り分ける | 夜に仕込んだエージェントの結果を検収する（思考が澄んでいる時間を判断に使う） |
| 日中 | リストから選んで逐次実行。2分ルールで小さい仕事をさばく | 何をやるかを決め、仕様を書いて投げる。人と話す時間が増える。結果を見て修正か採用か |
| アウトプット | 自分で書く | 構成は手伝ってもらうが、自分の名前で出すものは自分の言葉で書く（信用は委任で増えない） |
| 身体を使う趣味 | 行動を分解して管理 | ほぼ変わらない。委任できないし、したくもない |
| 効率を求めない遊び | 「気になること」が発生しない領域 | 判断から解放される領域（一日中決めた後の休息として価値が上がる） |
| 週次レビュー | リストの整理、抜け漏れの確認 | 「このひと月、自分は何を理解したか」の確認。ログの量ではなく血肉になった量を見る |

## 一言で

- GTD：頭を空にして、手を動かす時間を確保する
- ポストGTD：手は足りている。何を握り続けるかを選び、任せたものを理解して引き受ける

## 補足

- GTDの5ステップ（収集・見極め・整理・更新・実行）は捨てなくてよい。「見極め」と「更新」の重みが増し、「実行」の中身が「委任と検収」に置き換わるだけ。
- 自分で手を動かす時間をゼロにしない。検収の目を保つためだけでなく、何を頼めばいいかという発想自体が、自分で触った経験から出てくるため。
