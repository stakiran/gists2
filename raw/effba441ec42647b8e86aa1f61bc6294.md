# なぜ人は vibe coding に中毒になるのか（そして、ならない人はなぜならないのか）

AIコーディングにハマる人の心理についての考察メモ。「複雑でコンテキストスイッチも多い作業なのに、なぜ中毒的な消費になりうるのか」という疑問から始まった議論の整理。

## 前提の問い

vibe coding は複雑なことをしているし、コンテキストスイッチも多い。中毒になるほど「消費的で単純」な活動には見えない。なのに、なぜハマる人がいるのか？

## 1. 依存を生むのは「単純さ」ではなく「報酬の構造」

行動が習慣化・依存化しやすいかどうかを決めるのは、作業の単純さではなく報酬の構造。

- **変動比率強化スケジュール**: プロンプトを投げると数十秒後に結果が返るが、当たり外れはランダム。一発で動くこともあれば微妙に壊れていることもある。「当たるか分からないが、たまに大当たりする」構造はスロットマシンと同型で、行動を最も強く維持するパターン。
- **リトライコストが極端に低い**: 失敗しても「もう一回プロンプトを投げるだけ」。「あと一回だけ」が延々と続く。
- **努力と成果の比率が壊れている**: 従来のコーディングにあった長い苦労のフェーズを飛ばして「アイデア → 動くもの」が直結する。自分の意図が世界に反映される感覚（有能感・自己効力感）が数分単位で連続供給される。
- **「生産している」という自己正当化**: 純粋な消費コンテンツと違い罪悪感の歯止めが効きにくい。むしろたちが悪い。

コンテキストスイッチについては、生成待ちの空白時間がむしろ「常に何かが進行していて、常に確認したいことがある」状態を作る。これは深いフローというより通知を待つ落ち着かなさに近く、依存的なパターンと相性がいい。

## 2. ハマる人とハマらない人は「別の活動」をしている

「コンテキストスイッチがきつくて、疲れるからやりたくない」という感覚への答え。

- **疲れる人**: AIの出力をちゃんと読み、自分のコードのメンタルモデルと突き合わせて検証している。他人のコードのレビューは自分で書くより疲れる——vibe coding はそれを数分おきに強制してくる。消耗して当然。
- **ハマる人**: その検証を最初から放棄している。「動いたからOK、次」。コードの中身のメンタルモデルを維持しないので、**スイッチすべきコンテキストがそもそも存在しない**。認知的に軽いからこそ、スロット的な報酬ループが純粋に回る。

つまり疲れるかどうかは「どの深さでコードに関与するか」でほぼ決まる。深く関与する人ほど報酬よりコストが上回るので中毒になりようがない。コードに責任を持つ姿勢を降ろせないのは、むしろ健全な反応。

また単純な個人差もある。不確実な報酬を「待つ・確認する」こと自体を快と感じる人と、ストレスとして感じる人がいる。ギャンブルにハマる人と興味を持てない人がいるのと同じ。

## 3. ハマる人は「アイデアマン」なのか？

必ずしもそうではない。因果はむしろ逆で、「アイデアがあるからハマる」のではなく「ループ自体が楽しいから、アイデアが後付けで湧いてくる」。

- **アイデアの合格ラインが地面すれすれまで下がる**: 従来は「数週間かける価値があるか」というフィルターを通ったものだけがアイデアだった。数分で形になるなら「一瞬思いついた」程度の雑念で十分プロンプトになる。ハマる人がアイデア豊富に見えるのは、誰の頭にも流れている雑念がアイデアとして採用されているだけ。
- **アイデアは依存の原因ではなく燃料**: スロットを回す人はコインを入れたくて回しているのであって、出てくるものが欲しいとは限らない。作ったものの多くは一度動かして満足したら二度と開かれない。燃料は質より供給が続くことが大事。
- **道具が欲望を作る**: カメラを買うと撮りたいものが増えるのと同じで、「作れる」状態に置かれると「作りたいもの」が発生する。作らせたいものが思いつかないのは想像力の欠如ではなく、そのループに身を置いていないから欲望が製造されていないだけ。

## まとめ

- 依存を生むのは作業の単純さではなく、**低コスト・即時・不確実な報酬のループ**。複雑な生産活動でも十分成立する。
- 「vibe coding」という同じ名前の下で、検証する人としない人は**質的に別の活動**をしている。疲れる人は中毒になりようがない。
- アイデアの量は才能ではなく、作るコストの低下による**合格ラインの崩壊**の産物。
- 作らせたいものが思いつかないのは欠落ではなく、必要のフィルターが正常に機能しているということ。
